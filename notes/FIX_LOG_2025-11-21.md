# Fix Log - November 21, 2025

## 1. Select Mode CSS Issue
**Issue:** In the Code Editor's file explorer, enabling "Select Mode" caused file/folder names to truncate aggressively or disappear.
**Cause:** The CSS grid definition for `.fe-tree.fe-tree-select-mode > li` in `explorer.css` expected 5 columns (`24px 20px 20px 1fr auto`), matching the normal view layout. However, in select mode, the DOM structure is simplified (checkbox, icon, text), resulting in the text element being forced into a narrow grid track.
**Solution:** Updated `app/apps/file_editor_cm6/static/js/explorer.css` to define a correct 3-column grid (`24px 20px 1fr`) specifically for select mode rows.

## 2. Link to External File Explorer
**Issue:** Users needed a way to open the current project or directory in the full File Explorer app directly from the Code Editor's context menu.
**Cause:** Feature was missing.
**Solution:**
*   **Frontend (Code Editor):** Added an "Open in File Explorer" item to the folder context menu in `app/apps/file_editor_cm6/static/js/explorer.js`. Implemented navigation using `window.location.href` to point to `/app/file_explorer?path={encoded_path}`.
*   **Frontend (File Explorer):** Modified `app/apps/file_explorer/main.js` to check for a `path` query parameter during initialization. If present, this path now overrides the last saved state, enabling deep linking.

## 3. Blank File Glitch
**Issue:** Opening a completely empty file could cause UI instability or errors in the editor initialization.
**Cause:** The backend endpoint `set_editor_content` in `editor_app.py` could potentially receive or process `None` for the content of an empty file, leading to issues when calculating the SHA256 hash or passing data to the frontend editor component.
**Solution:** Added a defensive check in `app/apps/file_editor_cm6/nicegui_editor/editor_app.py`. The code now explicitly defaults `content` to an empty string `''` if the incoming payload is `None` before any processing occurs.
