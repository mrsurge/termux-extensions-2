# TE2 Repository Memory (Candidate)

This file is concise durable orientation. Current source is authoritative;
update or remove any memory entry that source supersedes.

## Workflow

- New repository changes use prompt approval, read-only investigation, final
  plan approval, then execution of only the approved scope.
- Preserve user changes and untracked files. `android/` is read-only unless an
  approved plan explicitly includes it.
- Never restart the shared TE2 framework runtime without explicit approval.
- Use `$TMPDIR` for scratch data when set; otherwise use a named workspace-local
  scratch directory rather than hard-coding `/tmp`.

## Runtime Authority

- The supported framework is the Rust server under `framework/rust/`.
- `te2` and `te2-rust` resolve through `app/cli/run_rust_framework.py`, which
  loads `framework/bootstrap/bootstrap.py`. The bootstrap builds/reuses a
  fingerprinted Rust binary, starts the Python runtime bridge, and forwards
  signals to the Rust server. `te2 console <command>` dispatches to
  `app/cli/console_cli.py` and does not load the bootstrap.
- The retired Python framework, supervisor, app lifecycle/runtime, generic
  extension backends, and duplicate Python Git provider were removed. Do not
  restore them as fallbacks. There is no Python compatibility framework or IPC
  lifecycle service.

## Retained Python Boundary

- Python is transitional support, not framework authority. Keep it only where
  current source imports it for CLI/bootstrap, TE2 console/MCP sidecar,
  manifest/scaffolding helpers, app workers, pipe support, or current app
  backends. Do not restore the retired Python framework,
  supervisor, app lifecycle, generic extension runtime, or duplicate Git
  provider.

## Framework And App Assets

- Rust serves the framework shell from `app/templates/` and `app/static/`.
- Built-in apps live under `app/apps/`; user-local apps live under
  `~/.local/share/te2/apps`.
- App manifests are the app catalog contract. Apps with semantic backend
  readiness opt in through `readiness_support: true` and publish readiness to
  `/api/apps/{app_id}/readiness`.
- Framework-readiness app shells use one app-scoped `/api/apps/events?app_id=...`
  SSE stream. Do not restore serialized catalog/settings/state/readiness GETs or
  `/ws/apps` as an app-shell boot gate.
- Framework services for filesystem, Git, search, bookmarks, settings, state,
  app lifecycle, proxying, and shell orchestration are Rust/Ferrous-owned.
- Framework settings persist only at
  `$TE2_CONFIG_HOME/framework/settings.json`. Generic state and bookmarks
  persist only at `$TE2_DATA_HOME/framework/state_store.json` and
  `$TE2_DATA_HOME/framework/bookmarks.json`. Ordinary runtime never probes the
  former `termux_extensions` cache tree.
- The vendored browser font in `app/static/fonts/jetbrains/webfonts/` is the
  complete Nerd Fonts v3.4.0 JetBrains Mono NFM glyph corpus, published as only
  Regular, Italic, Bold, and BoldItalic WOFF2 faces under the existing asset
  filenames. Do not restore the release archive, desktop TTFs, variable fonts,
  no-ligature duplicates, proportional variants, or unused weight files.

- TE2-owned per-app durable state resolves beneath
  `$TE2_DATA_HOME/app_state/<app_id>`; `$TE2_DATA_HOME/apps/<app_id>` remains
  installable user-app source and must not be reused as an app-state partition.
- Legacy recovery exists only through the standalone dry-run-first
  `te2 migrate-legacy-roots` command. `--apply` requires the framework to be
  stopped, takes framework/migration locks, validates an allowlist, stages
  atomic replacements, and writes a versioned one-time receipt. The legacy
  source destructively overwrites matching canonical files and modes while
  destination-only tree entries survive. Unknown/unowned content is
  report-only; ordinary startup never invokes this migration.

## Framework Network Exposure

- The Rust framework remains loopback-only by default. The Python bootstrap
  resolves `--broadcast` once into exact bind hosts and an immutable Rust
  `NetworkExposurePolicy`; invalid IP, CIDR, empty, or unresolved interface
  selectors fail before binding. `te2 --list-interfaces` uses libc
  `getifaddrs` and prints structured JSON on Linux and Termux/Android.
- Exact IP/CIDR selectors filter by peer address. Interface selectors filter by
  the accepted socket's local destination address, so unrelated interfaces are
  blocked and `/32` VPN adapters remain usable. Loopback is always admitted.
  One outer Axum middleware runs before HTTP, SSE, raw WebSocket, Socket.IO,
  app-proxy, console, and MCP routing.
- Public bind addresses and the internal framework origin are distinct. IPv4
  and IPv6 wildcard listeners use separate sockets; app workers,
  Framework-Shells, console, and MCP continue to receive a usable loopback
  `TE_FRAMEWORK_URL`, never `0.0.0.0` or `[::]`.

## Code TE2 Source And Ownership

- Code TE2 is `app/apps/code_te2` and its canonical public app id is
  `code_te2`. Host frontend entry is `main.ts`; host source lives under
  `main_page/frontend/`; generated host bundle is `static/dist/host.js`.
- The manifest's exact `file_editor_cm6` alias is a bounded request and
  persisted-state migration contract only. It resolves to the one canonical
  definition and must never create a second catalog entry, app worker,
  Framework-Shell identity, readiness record, or state authority. Newly
  generated URLs and runtime identities use only `code_te2`.
- Editor frontend entry is `monaco_editor/m_editor_app.ts`; editor source and
  editor backend services live under `monaco_editor/`.
- Explorer frontend lives under `src/explorer/`; Explorer backend/RPC code lives
  under `explorer/`. Host backend actions live under `host/`; UI and Sidebar IPC
  live under `ui_ipc/`; WBA lives under `workbench_protocol_proxy/`.
- Active-file authority is `ProjectSidecar.last_file`, coordinated through
  `open_state_backend.py` and editor open services. Frontend path variables are
  projections.
- Frontends use only their own RPC lanes: editor `/rpc/editor`, Explorer
  `/rpc/explorer`, host `/ui_ipc`, sidebar backends `/sidebar_ipc`, terminal
  `/terminal`, WBA `/wba`, and framework console `/te2_console`. The standalone
  terminal frontend additionally publishes only IME focus/blur hints to
  `/ui_ipc` for the native wrapper.
- The Python-owned Socket.IO namespaces (`/rpc/editor`, `/rpc/explorer`,
  `/ui_ipc`, `/sidebar_ipc`, `/terminal`) share the canonical public path
  `/api/app/code_te2/socket.io`, allowing one browser-realm Engine.IO Manager
  to multiplex them. WBA remains a separate direct hot path at
  `/api/app/code_te2/services/wba/socket.io`; the exact former full paths and
  established manifest path aliases are compatibility-only request aliases.
- Explorer, editor/Python, direct editor/WBA, and UI IPC require strict
  `msgpack-v1` application payloads over their existing Socket.IO namespaces.
  Browser encoding is owned by `src/rpc/codec.ts`; Python encoding, decoding,
  strict auth validation, and default-off stdout metrics are owned by
  `frontend_rpc_codec.py`; WBA runtime encoding is owned by
  `workbench_protocol_proxy/node_workbench_adapter/src/protocol/messagepack-codec.ts`.
  These migrated lanes have no JSON fallback. Sidebar IPC retains its current
  codec. `CODE_TE2_RPC_CODEC_METRICS=1` enables codec metadata on stdout;
  declared as `0` in the app-worker shellspec, inert while disabled.
- Direct editor/WBA language intelligence remains a frontend-to-WBA hot path.
  MessagePack changes its application payload codec only; it does not route
  hover, completion, symbols, semantic tokens, inlay hints, or other WBA calls
  through Python or the worker event bus.
- App-lane Socket.IO clients use websocket-only transports. Request/response
  RPC calls use ordinary `emit` only while connected; fire-and-forget
  notifications use `volatile.emit`. After first connect, disconnected RPC
  calls fail, in-flight requests reject, notifications drop, and each namespace
  clears its `sendBuffer`; explicit connect handlers rebuild authoritative
  state. Python `AsyncManager` has no disconnected-session recovery; WBA keeps
  `connectionStateRecovery` disabled.
- Cross-surface actions flow frontend -> own backend -> target backend hook ->
  target notification. Do not connect one frontend directly to another lane.
- Code TE2 Git and search jobs use Rust pipe services. The old generic Python
  Git job registration/listener is gone. `app.libs.jobs` remains imported by
  archive/file-explorer workers and stores records at
  `$TE2_DATA_HOME/framework/jobs.json`, but its `jobs_bp` has no current Rust
  framework mount; do not restore the retired global `/api/jobs` route as a
  fallback.

- Sidebar ledger v2 is membership-only: Python persists and projects stable
  slot identity, lifecycle/readiness, and surface metadata, but not dock order
  or a cross-client foreground. The obsolete
  `ui.sidebar.window.order.update` RPC is removed; activation is bounded
  client-scoped focus metadata rather than presentation authority.
- Each host owns versioned Sidebar presentation state containing local order,
  foreground host, last-agent host/presentation identity, and
  embedded/hidden/detached modes. Every ledger snapshot deterministically
  prunes missing slots, preserves surviving order, appends new slots, and
  selects a local foreground fallback. Browser and Gecko hosts use origin-local
  `localStorage`; Electron uses a validated preload/main bridge with an atomic
  XDG-config store. Exact former Code TE2 slot, presentation, and restore-URL
  identities are rewritten once and persisted canonically; canonical records
  win collisions.
- Sidebar mentions are exact-client presentation actions. Monaco,
  Explorer/search diagnostics, and Problems attach the originating client id,
  stable agent host id, and transient presentation id. The registered Sidebar
  host publishes those ephemeral presentation tuples on iframe
  creation/replacement and after every Sidebar IPC registration
  acknowledgement. Python derives client identity from that host connection,
  validates the tuple against the live host, membership-only ledger, agent
  conversation, and registered app peer, derives conversation identity from the
  ledger slot, and emits only to that app room. Missing or stale targets fail
  with no global-active or broadcast fallback.

- Code TE2 persistence uses one canonical partition: project sidecars,
  draft indexes, history, and agent icons live beneath
  `$TE2_DATA_HOME/code_te2`; preferences live beneath
  `$TE2_CONFIG_HOME/code_te2`; the Sidebar backchannel and code-server Unix
  sockets live beneath `$TE2_RUNTIME_HOME/code_te2`; and the remaining
  browser-console log lives beneath `$TE2_CACHE_HOME/code_te2`. Project-local
  diagnostics use `.code_te2/diagnostics`. Ordinary startup does not probe or
  import the former `cm6_editor`, `cm6_sessions`, `termux-extensions-2`, or
  `.code_cm6` roots. The proven-dead `cm6_sessions` helpers were removed;
  legacy root recovery belongs only to the explicit opt-in migration command.
  The exact framework `app_state:file_editor_cm6` key and old layout key have
  bounded destructive one-time moves to their `code_te2` equivalents; the
  canonical destination wins.
- The generic Python app worker resolves built-in backend module identity from
  the backend file's package path rather than from the public app id. A backend
  may export the authoritative `TE2_APP_ROUTER`; Code TE2 does. The legacy
  `<app_id>_bp` lookup remains only for existing out-of-tree apps that do not
  yet export the explicit contract.

- The ALS-RS Sidebar peer resolves its outbound `/sidebar_ipc` connection from
  the framework-injected `TE_FRAMEWORK_URL`, with `TE_PORT` and then `8089`
  only as standalone fallbacks. ALS-RS's own `12459` HTTP listener is unrelated
  to the framework port. Network and server disconnects reconnect event-wise,
  and every Socket.IO connection re-registers the exact `als-rs` app peer before
  targeted mentions can route.

## Code TE2 Search System

- Progressive content and file search are backed by the Rust `service.search`
  pipe. Python (`explorer/services/search_sessions.py`) is the session/cache
  owner and Explorer frontend adapter; it does not run the search itself.
- Explorer RPC methods: `explorer.search.run`, `explorer.search.more`,
  `explorer.search.moreInFile`, `explorer.search.cancel`. Result events:
  `explorer.search.results.updated`, `explorer.search.started`,
  `search.job.progress`, `search.job.result`, `search.job.done`,
  `search.job.error`. The stale `search:query` explorer bus event no longer
  exists.
- Python injects `maxMatchesTotal: 700` (in `explorer/search.py`) into every
  content search start so Rust stops walking after 700 matches. Rust reports
  truncation via `truncatedReason: "matchLimit"` plus a `matchLimit` field on
  each `SearchContentResult` and terminal `SearchJobDone`.
- Python's result cache uses typed slots dataclasses with tuple ranges for
  compact storage. Routed pipe notifications are parsed into compact search
  event context objects; outgoing socket payloads are built from session state,
  not copied from inbound pipe params.
- Active Python search sessions are removed from `_sessions` on supersede,
  overlay close, and project switch so dead sessions do not accumulate across a
  user session. Frontend `closeSearchOverlay` / project-switch paths must call
  `cancelSearch` and clear overlay UI.
- Rust search uses the `ignore`, `grep_regex`, and `grep_searcher` crates with a
  shared `Arc<RegexMatcher>` compiled once per search job. `search.config.get`
  reports search-thread resolution; per-request `searchThreads` wins, then
  Rust `TE2_RUST_SEARCH_THREADS`, then `available_parallelism - 1` with fallback
  4, clamped 1..64. Code TE2's `SEARCH_THREADS` env is converted by Python into
  a per-job `searchThreads` request, not a direct Rust global. Progress coalesces
  every 256 scanned files. The mpsc event queue is capacity 256 with
  required-result backpressure and optional-progress drop.

## Code TE2 Open-File And Document Lifetime

- See `docs/apps/code_te2/CODE_TE2.md` §39 for WBA logical documents and
  multi-file extension handling. Key invariants: visible open ends after Monaco
  model verification, not WBA acknowledgement; `editor.openComplete.publish` is
  the reliable control-plane acknowledgement; WBA retains active/background
  extension-host documents without LSP close/open churn; Python materializes
  only WBA-requested missing/stale background documents.

- WBA retained background documents prewarm only real full-document
  semantic-token providers. The serialized concurrency-one queue pauses during
  visible opens; foreground Monaco consumes exact maps through the existing
  `vscode.semanticTokens` call. Cache identity includes registry
  version/content identity/language/SHA-256 text fingerprint/project
  generation/full-provider generation. Range tokens stay live and range-bound;
  no fake ranges. Mutation, close, reset, full-provider change, or 32 MiB
  whole-entry LRU pressure evicts complete maps and releases provider result IDs.

- Foreground promotion retains its draft-safe full-text synchronization barrier,
  but a byte-identical update does not advance the WBA model version, emit a
  model-change event, or invalidate a prewarmed semantic-token map. The frontend
  reconciles WBA selectors into one stable provider per language, prefers full
  over range, ignores snapshot duplicates, and coalesces real provider/legend
  invalidations by language.

- Editor document admission is deny-based and runs during canonical
  materialization before active/recent sidecar mutation. Known binary, media,
  archive, object, and font extensions are rejected; extensionless executable
  files are rejected; disk or draft content over 375 KiB is rejected. Source
  formats remain open by default, including `.sh`. Monaco visible-open
  completion verifies the attached editor/model URI and does not wait for WBA
  acknowledgement.

## Code TE2 Code-Server And WBA Runtime

- Code TE2 has two mutually exclusive language-backend modes, persisted by the
  global `webWorkersEnabled` UI preference. Code Server mode resolves only the
  pinned TE2-managed runtime under `$TE2_DATA_HOME/code_server/4.130.0` after
  canonical root resolution. Managed resolution accepts only the exact private
  Linux standalone and Termux package layouts; it never walks upward into a
  system `/lib/code-server` tree. Worker mode does not prime WBA or Code Server,
  stops any live language-backend shells when selected, and preserves the
  installed managed runtime. A stale missing boot snapshot is refreshed before
  the frontend offers installation again.
- Code Server mode loads Monaco editor core without Monaco basic/rich language
  contributions or language workers. It obtains language/configuration/grammar
  metadata from WBA, applies contributed TextMate grammars client-side, and
  registers WBA-backed public Monaco providers. Provider selectors and WBA
  catalog order drive the path; do not add per-language routing branches or
  mutate Monaco's private provider registries.
- Worker mode lazy-loads Monaco contributions/workers and does not connect to,
  probe, or register providers from WBA. The two modes have no fallback into
  one another.
- WBA document highlights back Monaco cursor-occurrence highlighting.
  Definitions, references, and implementations also project through public
  Monaco provider APIs. Call hierarchy remains in Code Inspector because
  Monaco's public language API has no call-hierarchy registration surface.
- The confirmed private Code Server installer is pinned to 4.130.0 and is too
  detailed for repo memory; see `docs/apps/code_te2/CODE_TE2.md` §41. The
  bootstrap must not vendor the 709 MiB tree or register the package with `apt`.
- The managed executable and mutable code-server state are separate. The
  executable remains beneath `$TE2_DATA_HOME/code_server/4.130.0`; Code TE2's
  private User data, extensions, registry, and settings live beneath
  `$TE2_DATA_HOME/code_te2/code_server`; and its Unix socket lives at
  `$TE2_RUNTIME_HOME/code_te2/code_server.sock`. Extension CLI operations
  receive both private directory arguments. Ordinary startup and WBA never
  probe the user's global `~/.config/code-server`.
- WBA receives exact extension-manifest, User-settings, and generated RPC
  configuration paths from its Framework-Shell environment. Generated probes
  remain beneath `$TE2_CACHE_HOME/code_server/probes`.
- WBA MessagePack codec installs as one self-contained bundled ESM file at
  `workbench_protocol_proxy/node_workbench_adapter/dist/protocol/messagepack-codec.mjs`;
  installed runtimes must not resolve `@msgpack/msgpack` from `node_modules`.
- WBA protocol actors use named `_rpcIds` lookups populated from the generated
  managed-runtime config. `RPC_DEFAULTS` is only the pinned Code Server 4.130
  no-config fallback; production extraction remains authoritative. Extension
  activation and language ID resolution are summarized in
  `docs/apps/code_te2/CODE_TE2.md` §39.

- Languages & Extensions exposes only User and Workspace settings scopes. The
  User schema forms and User JSON editor share registry v2 `user_settings`,
  atomically materialized with TE2 gates to
  `$TE2_DATA_HOME/code_te2/code_server/User/settings.json`; WBA maps it only
  to `userRemote` and leaves `userLocal`/profile tiers empty.
- Workspace schema forms and JSON edit the active project's
  `.vscode/settings.json`, projected through `workspace` and `folders[0]`.
  Registry v1 `configuration_values` and `custom_settings` migrate once into
  the shared User map, with explicit legacy User JSON winning conflicts.

- WBA activation remains event-wide: opening a document activates every
  extension matched by `onLanguage:<id>` and generic `onLanguage`.
  Document-scoped provider dispatch then matches every registered selector
  against the exact language, scheme, authority, and path before aggregating
  results. Pattern-only selectors are valid and must not be dropped merely
  because they omit a `language` field.
- Extension-host `workspace.findFiles` uses WBA's generic bounded
  `$startFileSearch` implementation. It searches the requested relative root
  or active workspace, honors explicit VS Code include/exclude globs and result
  limits, and returns URI components with the current WBA scheme and authority.
  Do not restore the empty-array stub; workspace-scanning extensions depend on
  these results before their providers can return useful data.

- WBA hover provider aggregation remains ordered and language-generic. The editor frontend recognizes legacy `{ language, value }` marked-code records before ordinary Markdown and preserves only type-valid Code OSS Markdown trust, HTML/theme/alert, base-URI, and URI-map metadata; malformed fields do not pass through to Monaco.

- Before returning a non-empty hover, the editor extracts fenced-code language tags, resolves them through Monaco's contributed language IDs and aliases, and awaits the existing WBA TextMate tokenizer for each language. This is generic, handles a hover fence language differing from the active model, and rejects the result if cancellation or document-version drift occurs during grammar loading.

- WBA language declarations with the same ID compose generically. Association arrays are unioned; higher-priority user metadata wins where supplied; and language-configuration ownership changes only when that contribution provides readable raw configuration. Partial user declarations must not erase built-in brackets, auto-closing pairs, surrounding pairs, or indentation/on-enter rules.

- Installed WBA runtimes must not resolve production Node dependencies from
  source `node_modules`. `picomatch` is packaged beneath
  `app/apps/code_te2/vendor/picomatch` and the generated provider registry loads
  that exact vendored path; the installed-wheel regression test exercises
  selector matching from an isolated package-shaped tree.

- The first UI VSIX slice supports workspace-scoped activity-bar webviews. The existing extension registry remains install/enablement authority, and User/Workspace settings remain in the existing registry plus active-project `.vscode/settings.json` projection; webview presentation must not add another project or configuration authority.
- WBA owns one logical `ExtensionWebviewSurface` per workspace/view, implements the Code Server 4.130 webview RPC actors, and uses strict MessagePack plus binary-preserving Code OSS mixed arguments for browser/extension-host messaging. A trusted wrapper hosts sandboxed extension HTML, and local resources require realpath containment beneath `localResourceRoots`.
- Complete WBA surface snapshots project through Python into ordinary Sidebar URL membership. Browser and GeckoView remain inline; Electron reuses its existing detach/attach presentation. Activity-view Close is client-local `hidden` presentation state: backend membership and the contained contributed icon remain in the Extension Views app drawer for reopening. Workspace switch, provider unregister, failed resolve, WBA reset, and stale snapshots remove membership. User-created URL slots retain destructive close behavior.

- WBA's bounded command/menu runtime reads manifest commands plus `editor/title`, `editor/context`, `editor/title/context`, `explorer/context`, and `webview/context`. It retains icon, group/order, `when`, enablement, alternate-command, and extension-defined `setContext` state; uses vendored `picomatch` for brace-capable `workspaceContains`; activates `onCommand`; and invokes `ExtHostCommands`. The touch editor installs one stable Extension Context launcher and resolves its current actions only when opened. Explorer actions originate only through `/rpc/explorer`; Python validates clicked and selected project resources before WBA resolves or executes them. Webview context uses the authoritative `webviewId` plus bounded primitive element context and never performs editor-selection sync. `MainThreadMessageService` projects extension messages through the existing editor notification path. Resolution is event-driven; there is no selection polling.
- Code Server's management scan remains WBA extension-admission authority, but
  matching admitted non-builtin extensions receive manifest-owned fields from
  their canonical private `extensions.json` packages. Management runtime
  identity/location wins, and disk-only extensions are never admitted. This
  repairs partial scan DTOs that omit commands or menus without bypassing Code
  Server enablement or compatibility decisions.
- WBA implements bounded Code Server 4.130 `MainThreadTextEditors` navigation for `showTextDocument`, show/focus, selection, and reveal, plus internal `_workbench.open`. File opens use a correlated WBA-to-Python request, Code TE2's canonical project-contained backend open, and Monaco's existing `editor.openComplete.publish` acknowledgement before WBA returns its logical editor id. Unsupported editor mutation/hide calls fail explicitly. Workspace reset cancels pending navigation and clears extension context; no navigation path polls.
- After awaiting `onCommand` activation, WBA invokes
  `ExtHostCommands.$executeContributedCommand` directly. The extension host is
  the command-registration authority and returns the canonical missing-command
  error; WBA must not block execution on its `MainThreadCommands` mirror.

- Ordinary extension webview panels share the activity-view opaque sandbox, resource containment, storage, theme, and MessagePack document runtime, but retain separate WBA/extension-host lifecycle through `MainThreadWebviewPanels` and `ExtHostWebviewPanels`. Panels project as temporary Sidebar membership; Close routes through host UI IPC and truly disposes the WBA panel. Custom editors, generic diffs, `view/title` placement, targeted initial reveal, and multiple Codex conversations remain deferred; see `docs/apps/code_te2/CODE_TE2.md` §44.

- UI VSIX documents keep an opaque sandbox origin. Browser, Electron, and Gecko resolve one stable `clientInstanceId`; each page also owns a reload-stable `windowId`, while inline/detached incarnations use transient `presentationId` values. Main-page console worker ids are `main_page:<clientInstanceId>:<windowId>`, an observability projection rather than state authority. Browser identity uses `localStorage`, Electron persists beneath `$TE2_CONFIG_HOME`, and Gecko reuses its application-private installation id through the always-on asset-intercept bridge.
- WBA persists bounded opaque webview reconstruction records beneath `$TE2_DATA_HOME/code_te2/code_server/User/te2-webview-reconstruction`, keyed by `(clientInstanceId, surfaceId)`. Each attach mints a current writer lease and one-time document token; VS Code API state and persistent Web Storage are injected synchronously before extension scripts. Only a strictly newer revision from the current lease is accepted, so stale inline/detached renderers cannot overwrite their replacement. Reset is confirmation-gated, deletes only that client's records, then replaces the client identity and reloads. Sidebar membership and extension semantic state remain separate authorities. Keep the opaque sandbox; never add `allow-same-origin` as a storage workaround.

- UI VSIX webviews currently use the required vendored GitHub Dark Default payload as a fixed host theme, independent of Monaco's selectable editor theme. WBA injects Code Server-compatible `--vscode-*` variables plus `vscode-dark` body metadata before extension scripts run; missing or mismatched theme assets fail initialization. Dynamic WBA-provided themes remain deferred.

- UI VSIX wrapper bootstrap dependencies are WBA-owned. The wrapper loads `./runtime/socket.io.min.js`, served from the existing `code_te2/vendor/node_socketio` package beside the bundled MessagePack codec. Do not route this script through global `/static/vendor/` assets; Gecko subframe asset interception can break that redirected nested script load.

- WBA implements Code Server 4.130 `MainThreadStorage` for generic extension `globalState` and `workspaceState`. Python injects the exact `$TE2_DATA_HOME/code_te2/code_server/User/te2-extension-storage` root; global Mementos are keyed by canonical extension id, workspace Mementos additionally by resolved workspace identity, and writes use serialized atomic replacement. `$registerExtensionStorageKeysToSync` is intentionally local-only because TE2 does not implement Settings Sync. Webview Web Storage, extension settings, and extension-context Mementos remain separate authorities.

- Extension webview-panel DTO translation accepts Code OSS's nested `WebviewExtensionDescription.id` identity. Symbolic negative placement requests such as `ViewColumn.Beside` are intent only; because TE2 has one Sidebar presentation column, WBA reports canonical editor-group position `0` to the extension host and in surface snapshots. Python continues rejecting identity-less surfaces rather than inventing an owner.

- UI VSIX keeps the trusted wrapper under its tight CSP and loads extension HTML as a direct sandboxed `/document` navigation rather than `srcdoc`. The requested resource origin must exactly match the wrapper request's HTTP(S) `Referer` origin before WBA transforms the document. This preserves the extension-authored CSP for workers and WebAssembly without granting `unsafe-eval` to the trusted wrapper.

- Active Monaco cursor/selection state projects event-wise over the direct strict-MessagePack WBA lane into `ExtHostEditors.$acceptEditorPropertiesChanged`, updating both `activeTextEditor.selection` and `onDidChangeTextEditorSelection`. The frontend coalesces bursts to at most one notification per 16 ms; disconnected notifications drop, and one exact snapshot is resent only after WBA acknowledges the active-document open. Command-time selection sync remains the final execution barrier. No selection polling or reconnect-era replay is permitted.

- WBA menu `when` evaluation treats unprojected positive context keys as false while preserving unquoted right-hand comparison literals such as `.json`. Unsupported Debug Pretty Print and Copilot active-diff editor-title actions remain suppressed by eligibility until their real context and editor semantics are projected; do not replace this with command-id or title blacklists.

- UI VSIX transport lifetime is separate from extension-document lifetime. WBA assigns a process epoch plus per-client activity-runtime generation, HTML revision, and monotonic server-event sequence, retaining at most 256 events and 2 MiB per runtime. A genuinely new document bootstrap receives only the retained message suffix after the current HTML revision's last authoritative reload boundary and queues it until the inner document is ready; a missing boundary is an incomplete bootstrap, never an arbitrary partial replay. Reconnect returns an explicit `resume`, bounded `replay`, or `reload`; valid resume/replay preserves the live iframe, while epoch/generation/revision change, replay gap, or authoritative reload/dispose reconstructs it. Disconnect rejects pending interactive RPCs and clears Socket.IO buffering without replay. The latest local reconstruction projection survives, renews its writer lease, and coalesces one newer write after reconnect. The generic Sidebar URL-slot version never reloads an `ExtensionWebviewSurface` outer wrapper for a WBA HTML revision; WBA alone reconstructs the sandboxed inner document. Within one WBA epoch/runtime generation, buffered events already covered by the latest attach sequence are discarded before HTML-revision comparison, preventing stale temporary revisions from starting an attach loop. Ordinary URL slots retain version-triggered reload. The lane remains strict MessagePack Socket.IO; raw WebSocket is deferred pending live acceptance.

- Activity-view membership is shared per workspace/view, but the resolved Code OSS runtime is lazy and client-scoped. The first attach creates one handle per `(surfaceId, clientInstanceId)` with exact-client HTML/options/state, resource capability, event journal, and browser-message routing. Client resolve failure is isolated; provider/workspace/WBA teardown removes all runtimes. Ordinary webview panels retain their extension-created lifecycle.
- UI VSIX resource URLs use a reference-counted, unguessable WBA-epoch scope keyed by extension, workspace, extension location, and normalized `localResourceRoots`. Identical activity views and panels reuse the same browser-cacheable URL without sharing document or extension-host lifecycle; every read still requires exact realpath containment. Extension-install assets use private immutable caching bounded by the scope token, while mutable roots retain ETag/Last-Modified revalidation. Compressible resources use asynchronous Brotli/gzip. Rust app and bridge proxies use a reqwest client without response decoders and therefore must preserve end-to-end `Content-Encoding` with the unchanged encoded body while allowing Axum to own downstream framing.

  those transports. A restarted service reads settings but never restores
  cached route authority. Persistent remote mode is explicit and
  non-loopback-only; while a remote app is active it uses the `connectedDevice`
  foreground-service type plus scoped partial CPU and active-Wi-Fi locks,
  exposes battery-optimization status/settings, and remains valid when
  notification permission is denied. Task removal, app-shell exit, timeout,
  retarget cleanup, or service shutdown releases ownership and power resources.

- Cefrium defers the first native Inspector runtime/browser startup until the main browser completes a real framework-relay document navigation and the persisted Tools state exposes Inspector. After first start, hiding Tools pauses presentation but retains the runtime/browser. Inspector document readiness comes only from its exact-origin `client_ready` query; Cefrium browser-wide loading callbacks also observe Chii child-frame loads and must never clear readiness or delivered target generation, or `target_reset` recreates the iframe in a reload loop that competes with main-page loading.

## Desktop Client

- `desktop_client/electron/` is the active Linux desktop client (Electron
  43.1.1, Ozone/Wayland). GTK 4/WebKitGTK 6 in `desktop_client/ui.py` is a
  behavioral reference only. The former Electrobun experiment is absent and
  must not be referenced as a current source tree.
- See `docs/apps/code_te2/CODE_TE2.md` §38 for Code TE2 desktop integration.
  Essentials: Electron uses a trusted `te2-desktop://shell/` root plus separate
  framework `WebContentsView`; one loopback relay origin proxies HTTP/SSE/
  Socket.IO/WebSocket and serves inventory-approved assets; app URLs carry
  `gv_native=1`; app views expose frozen `window.te2Electron` with exact-view
  allowlisted commands.
- Linux launch paths intentionally pass `--no-sandbox`; `package.mjs` emits the
  packaged launcher. Native Quit is app-scoped and returns to the desktop
  launcher without terminating Electron.

- Electron main receives authoritative owner/shell route snapshots through its
  direct strict-MessagePack Code TE2 UI IPC client and proactively reconciles
  listener groups from each projection event. App navigation loads the shared
  app shell immediately so manifest readiness remains visible. After backend
  readiness and before frontend injection, only Code TE2 awaits the first
  current Run Target projection through an exact-view preload prerequisite;
  every other app is a no-op. The wait is event-driven without an independent
  timeout, and the preload exposes no Run Target resolve operation.
  Only a configured `localhost`, `127.0.0.1`, or `::1` origin is local; every
  other configured host is remote without a health, DNS, or loopback-port
  identity probe. `EADDRINUSE` is a collision. UI IPC interruption preserves
  listeners and gates navigation; reconnect or full client restart reconstructs
  state from one snapshot. There is no route polling.

- Electron main owns `ElectronRunProfileRuntime` for `devRuntime` surfaces. The
  framework session applies exact-origin HTTP cache policy while excluding
  WebSockets, and exact marked subframes receive the shared console bridge only
  after surface, frame origin, and relay framework origin validation.
  `registerRunTargetSurface` and `releaseRunTargetSurface` manage only this
  instrumentation policy.

- Electron extension Sidebar surfaces use one framework-partition
  `WebContentsView` from their first embedded presentation. Code TE2 owns a DOM
  placeholder that reports bounds and visibility; Electron retains the live
  renderer while embedded, hidden, or detached and reparents that exact view
  between the main window and floating `BrowserWindow` without navigation,
  wrapper reconnect, presentation-id replacement, writer-lease replacement, or
  JavaScript-heap loss. A main-page reload temporarily hides the retained view
  until the new host reports placement. Ordinary URL and Run Profile surfaces
  retain the reconstruction path. Backend slot removal, app-view loss,
  framework retarget, or process exit disposes the native presentation.

- The Electron Sidebar dock's icon/action, refresh, and app-drawer menus use one
  exact-view, bounded OS-native menu bridge. Electron accepts only declarative
  labels, separators, enabled action ids, and coordinates, then returns the
  selected id; Code TE2 remains action authority. Browser and Gecko keep the
  existing DOM menus.

- Electron Run Target relay lifetime is exact Framework-Shell
  `ownerId + shellId`, not app-view or `surfaceId` lifetime. Detach, attach,
  window close, and surface release do not close a still-running shell's relay
  group; surface release remains runtime/cache/console policy cleanup.
  Framework route projection removal, retarget, and process exit close the
  listener groups.

- Electron settings and Sidebar presentation state resolve beneath
  `$TE2_CONFIG_HOME`; installed desktop assets resolve beneath
  `$TE2_DATA_HOME/desktop_assets`. Explicit `TE2_*_HOME` values are final
  roots, while XDG values are bases that receive `/te2`; no old desktop path
  is probed as a fallback.

## Shared Modal Architecture

- Async `teUI.dialog` replaces browser `alert`/`confirm`/`prompt`. Browser and
  Android stay inline; Electron uses portable IPC child windows plus stateful
  same-origin `about:blank` portal adoption. `te_dialog.mjs` owns the portable
  contract; `te_modal_surface_portal.mjs` owns Electron stateful adoption.
- Shared `teUI` select listboxes are fixed popups owned by the active dialog
  layer and measured against the visual viewport. Do not nest an open listbox
  under `.te-dialog-body`; its required `overflow-y: auto` clips overlays.
- Keep CM6 JSON fields in Run Profiles and Settings. Code TE2 reusable modal UI
  components live under `main_page/frontend/ui/modal-kit/`. Deep modal details
  belong in `docs/apps/native-js-modal-plan-tracker/`, not repo memory.

- Code TE2's dependency-free reusable DOM component core lives under
  `main_page/frontend/ui/component-runtime/`. It provides synchronous
  document-aware JSX, object refs, hierarchical owner/disposal scopes, owned
  event/subscription cleanup, and a small state projection controller; it is not
  a virtual DOM or state authority. `ui/modal-kit/jsx-runtime.ts` is the
  compatibility re-export. Modal shell destruction disposes the owned JSX
  lifecycle before removing its DOM.
