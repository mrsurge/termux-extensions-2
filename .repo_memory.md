# TE2 Repository Memory (Candidate)

This file is concise durable orientation. Current source is authoritative;
update or remove any memory entry that source supersedes.

## Workflow

- New repository changes use prompt approval, read-only investigation, final
  plan approval, then execution of only the approved scope.
- Preserve user changes and untracked files. `android/` is read-only unless an
  approved plan explicitly includes it.
- Never restart the shared TE2 framework runtime without explicit approval.
- Use `$TMPDIR` for scratch data when set; otherwise use a named workspace-local
  scratch directory rather than hard-coding `/tmp`.

## Runtime Authority

- The supported framework is the Rust server under `rust-spike/rust/`.
  `rust-spike` is a historical path name, not an indication that the Python
  framework remains primary.
- `te2` and `te2-rust` resolve through `app/cli/run_rust_framework.py`, which
  loads `rust-spike/app/bootstrap.py`. The bootstrap builds/reuses a
  fingerprinted Rust binary, starts the Python runtime bridge, and forwards
  signals to the Rust server. `te2 console <command>` dispatches to
  `app/cli/console_cli.py` and does not load the bootstrap.
- The retired Python framework, supervisor, app lifecycle/runtime, generic
  extension backends, and duplicate Python Git provider were removed. Do not
  restore them as fallbacks. There is no Python compatibility framework or IPC
  lifecycle service.

## Retained Python Boundary

- Python is transitional support, not framework authority. Keep it only where
  current source imports it for CLI/bootstrap, TE2 console/MCP sidecar,
  manifest/scaffolding helpers, app workers, pipe support, archive jobs, or
  current app backends. Do not restore the retired Python framework,
  supervisor, app lifecycle, generic extension runtime, or duplicate Git
  provider.

## Framework And App Assets

- Rust serves the framework shell from `app/templates/` and `app/static/`.
- Built-in apps live under `app/apps/`; user-local apps live under
  `~/.local/share/te2/apps`.
- App manifests are the app catalog contract. Apps with semantic backend
  readiness opt in through `readiness_support: true` and publish readiness to
  `/api/apps/{app_id}/readiness`.
- Framework-readiness app shells use one app-scoped `/api/apps/events?app_id=...`
  SSE stream. Do not restore serialized catalog/settings/state/readiness GETs or
  `/ws/apps` as an app-shell boot gate.
- Framework services for filesystem, Git, search, bookmarks, settings, state,
  app lifecycle, proxying, and shell orchestration are Rust/Ferrous-owned.
- The vendored browser font in `app/static/fonts/jetbrains/webfonts/` is the
  complete Nerd Fonts v3.4.0 JetBrains Mono NFM glyph corpus, published as only
  Regular, Italic, Bold, and BoldItalic WOFF2 faces under the existing asset
  filenames. Do not restore the release archive, desktop TTFs, variable fonts,
  no-ligature duplicates, proportional variants, or unused weight files.

## Code TE2 Source And Ownership

- Code TE2 is `app/apps/file_editor_cm6`. Host frontend entry is `main.ts`;
  host source lives under `main_page/frontend/`; generated host bundle is
  `static/dist/host.js`.
- Editor frontend entry is `monaco_editor/m_editor_app.ts`; editor source and
  editor backend services live under `monaco_editor/`.
- Explorer frontend lives under `src/explorer/`; Explorer backend/RPC code lives
  under `explorer/`. Host backend actions live under `host/`; UI and Sidebar IPC
  live under `ui_ipc/`; WBA lives under `workbench_protocol_proxy/`.
- Active-file authority is `ProjectSidecar.last_file`, coordinated through
  `open_state_backend.py` and editor open services. Frontend path variables are
  projections.
- Frontends use only their own RPC lanes: editor `/rpc/editor`, Explorer
  `/rpc/explorer`, host `/ui_ipc`, sidebar backends `/sidebar_ipc`, terminal
  `/terminal`, WBA `/wba`, and framework console `/te2_console`. The standalone
  terminal frontend additionally publishes only IME focus/blur hints to
  `/ui_ipc` for the native wrapper.
- The Python-owned Socket.IO namespaces (`/rpc/editor`, `/rpc/explorer`,
  `/ui_ipc`, `/sidebar_ipc`, `/terminal`) share the canonical public path
  `/api/app/file_editor_cm6/socket.io`, allowing one browser-realm Engine.IO
  Manager to multiplex them. WBA remains a separate direct hot path at
  `/api/app/file_editor_cm6/services/wba/socket.io`; framework console and
  manifest aliases are compatibility-only.
- Explorer, editor/Python, direct editor/WBA, and UI IPC require strict
  `msgpack-v1` application payloads over their existing Socket.IO namespaces.
  Browser encoding is owned by `src/rpc/codec.ts`; Python encoding, decoding,
  strict auth validation, and default-off stdout metrics are owned by
  `frontend_rpc_codec.py`; WBA runtime encoding is owned by
  `workbench_protocol_proxy/node_workbench_adapter/src/protocol/messagepack-codec.ts`.
  These migrated lanes have no JSON fallback. Sidebar IPC retains its current
  codec. `FILE_EDITOR_CM6_RPC_CODEC_METRICS=1` enables codec metadata on stdout;
  declared as `0` in the app-worker shellspec, inert while disabled.
- Direct editor/WBA language intelligence remains a frontend-to-WBA hot path.
  MessagePack changes its application payload codec only; it does not route
  hover, completion, symbols, semantic tokens, inlay hints, or other WBA calls
  through Python or the worker event bus.
- App-lane Socket.IO clients use websocket-only transports. Request/response
  RPC calls use ordinary `emit` only while connected; fire-and-forget
  notifications use `volatile.emit`. After first connect, disconnected RPC
  calls fail, in-flight requests reject, notifications drop, and each namespace
  clears its `sendBuffer`; explicit connect handlers rebuild authoritative
  state. Python `AsyncManager` has no disconnected-session recovery; WBA keeps
  `connectionStateRecovery` disabled.
- Cross-surface actions flow frontend -> own backend -> target backend hook ->
  target notification. Do not connect one frontend directly to another lane.
- Code TE2 Git and search jobs use Rust pipe services. The old generic Python
  Git job registration/listener is gone; generic Python jobs remain only for
  current non-Git app work such as archive extraction.

## Code TE2 Search System

- Progressive content and file search are backed by the Rust `service.search`
  pipe. Python (`explorer/services/search_sessions.py`) is the session/cache
  owner and Explorer frontend adapter; it does not run the search itself.
- Explorer RPC methods: `explorer.search.run`, `explorer.search.more`,
  `explorer.search.moreInFile`, `explorer.search.cancel`. Result events:
  `explorer.search.results.updated`, `explorer.search.started`,
  `search.job.progress`, `search.job.result`, `search.job.done`,
  `search.job.error`. The stale `search:query` explorer bus event no longer
  exists.
- Python injects `maxMatchesTotal: 700` (in `explorer/search.py`) into every
  content search start so Rust stops walking after 700 matches. Rust reports
  truncation via `truncatedReason: "matchLimit"` plus a `matchLimit` field on
  each `SearchContentResult` and terminal `SearchJobDone`.
- Python's result cache uses typed slots dataclasses with tuple ranges for
  compact storage. Routed pipe notifications are parsed into compact search
  event context objects; outgoing socket payloads are built from session state,
  not copied from inbound pipe params.
- Active Python search sessions are removed from `_sessions` on supersede,
  overlay close, and project switch so dead sessions do not accumulate across a
  user session. Frontend `closeSearchOverlay` / project-switch paths must call
  `cancelSearch` and clear overlay UI.
- Rust search uses the `ignore`, `grep_regex`, and `grep_searcher` crates with a
  shared `Arc<RegexMatcher>` compiled once per search job. `search.config.get`
  reports search-thread resolution; per-request `searchThreads` wins, then
  Rust `TE2_RUST_SEARCH_THREADS`, then `available_parallelism - 1` with fallback
  4, clamped 1..64. Code TE2's `SEARCH_THREADS` env is converted by Python into
  a per-job `searchThreads` request, not a direct Rust global. Progress coalesces
  every 256 scanned files. The mpsc event queue is capacity 256 with
  required-result backpressure and optional-progress drop.

## Code TE2 Open-File And Document Lifetime

- See `docs/apps/code_cm6/CODE_TE2.md` §39 for WBA logical documents and
  multi-file extension handling. Key invariants: visible open ends after Monaco
  model verification, not WBA acknowledgement; `editor.openComplete.publish` is
  the reliable control-plane acknowledgement; WBA retains active/background
  extension-host documents without LSP close/open churn; Python materializes
  only WBA-requested missing/stale background documents.

- WBA retained background documents prewarm only real full-document
  semantic-token providers. The serialized concurrency-one queue pauses during
  visible opens; foreground Monaco consumes exact maps through the existing
  `vscode.semanticTokens` call. Cache identity includes registry
  version/content identity/language/SHA-256 text fingerprint/project
  generation/full-provider generation. Range tokens stay live and range-bound;
  no fake ranges. Mutation, close, reset, full-provider change, or 32 MiB
  whole-entry LRU pressure evicts complete maps and releases provider result IDs.

- Foreground promotion retains its draft-safe full-text synchronization barrier,
  but a byte-identical update does not advance the WBA model version, emit a
  model-change event, or invalidate a prewarmed semantic-token map. The frontend
  reconciles WBA selectors into one stable provider per language, prefers full
  over range, ignores snapshot duplicates, and coalesces real provider/legend
  invalidations by language.

## Code TE2 Code-Server And WBA Runtime

- Code TE2 has two mutually exclusive language-backend modes, persisted by the
  global `webWorkersEnabled` UI preference. Code Server mode resolves only the
  pinned TE2-managed runtime under `$XDG_DATA_HOME/te2/code_server/4.130.0`;
  Worker mode does not prime WBA or Code Server.
- The confirmed private Code Server installer is pinned to 4.130.0 and is too
  detailed for repo memory; see `docs/apps/code_cm6/CODE_TE2.md` §41. The
  bootstrap must not vendor the 709 MiB tree or register the package with `apt`.
- WBA MessagePack codec installs as one self-contained bundled ESM file at
  `workbench_protocol_proxy/node_workbench_adapter/dist/protocol/messagepack-codec.mjs`;
  installed runtimes must not resolve `@msgpack/msgpack` from `node_modules`.
- WBA nid extraction uses named `_rpcIds.ExtHostLanguageFeatures` lookups; `94`
  is only the Code OSS 1.109 fallback. Extension activation and language ID
  resolution are summarized in `docs/apps/code_cm6/CODE_TE2.md` §39.

## Code TE2 Diagnostics

- Editor diagnostics remain direct WBA-to-Monaco state. `diagnostics_bridge.py`
  owns only the backend diagnostics projection consumed by Explorer/Problems;
  it must not import `editor_ws` or emit editor diagnostic counts. The obsolete
  `/workbench_adapter/nudge` route and its `vscode.openFile(forceRefresh=true)`
  adapter call were removed; do not restore a Python diagnostics nudge into the
  editor/WBA hot path.
- WBA pipe push handling uses one ordered app-worker drain. Contiguous
  `diagnostics/update` pushes coalesce latest-wins by `(owner, uri)`;
  non-diagnostics events remain ordering barriers. This prevents Python
  diagnostics storms from starving UI IPC/editor Socket.IO lanes on the shared
  asyncio loop.
- A default-off diagnostics/open latency recorder exists for proving Python
  diagnostics-storm contention. `FILE_EDITOR_CM6_DIAGNOSTICS_LATENCY_METRICS=1`
  and `window.__te2DiagnosticsOpenProbe` are both inert by default and must not
  become a scheduling or transport dependency.

## Code TE2 Editor UI

- The inline Monaco editor host remains at `z-index: auto`. Only its
  `.find-widget` is raised to `z-index: 300`, above drawers and resize handles
  but below framework dropdowns and modals; editor-container overflow clipping
  remains intentional.
- Default Monaco font is the vendored `JetBrains Mono Nerd` family under
  `app/static/fonts/jetbrains/webfonts/` with `fontLigatures` enabled.
- Code TE2 has no `.fe-menubar`. File, Edit, Editor, View, and the Git branch
  selector live in `.fe-toolbar`; the active filename is represented by the
  horizontal file-tab strip. Tabs use the vendored Seti icon provider with a
  generic Codicon fallback and square Explorer-derived Git/draft/diagnostic
  styling. Open-state hydration and active-file changes reveal the active tab;
  decoration-only renders do not move the strip.
- `file_tabs_projection.py` consumes existing open-state, Git, draft, and
  diagnostics facts. It coalesces projection work off-loop and emits only
  recent-path decoration summaries through `ui.fileTabs.decorations.changed`. It
  must not call `load_or_create(...).reload()` from a background thread.
- File tabs represent draft state with a red asterisk immediately before the
  filename.
- The Explorer header projects the current Git branch as `branch @ short-hash`
  from the existing `explorer.git.status.updated` snapshot, not the project
  directory name.
- Code TE2 Run execution is backend-owned and serialized per project. A profile's
  `saveDrafts` policy is `included`, `opened`, `all`, or `none`. Confirmation
  revalidates the target/profile selection before writes; stale confirmation,
  a tab switch, or any required save error prevents launch.
- The normal mobile terminal drawer is capped at 397 px through the shared
  `ui/drawer-sizing.ts` clamp. The `.fullscreen` drawer mode is exempt and
  applies to Terminal, Console, Problems, Extensions, and Code Inspector.
- The Explorer owns a separate Open VSX marketplace overlay triggered by its
  `🧩` header button. It uses the existing strict MessagePack `/rpc/explorer`
  lane; the Python backend performs bounded requests to the public Open VSX API
  and installs through the already-resolved code-server CLI and shared extension
  directory.

- Clean expanded Explorer directory scopes use stable DOM-depth parity: the project root is depth 0 and remains on the base card background, while odd-depth expanded directories receive a theme-adaptive 4% `currentColor` blend. Any non-clean `data-git-status` or `data-git-flags` suppresses this neutral band, including modified-border states; draft and diagnostic decoration layers do not. Sticky scope rows copy the innermost represented directory's open/depth parity and Git metadata so compressed scopes preserve the same visual contract.

- In desktop/landscape layout, `.fe-toolbar` owns stacking level 40 and the tiled `.agent-drawer` owns level 50. The toolbar's parent stacking context intentionally keeps every toolbar control and dropdown beneath the open Sidebar; mobile retains its separate existing layering.

- Inline diff originals are fetched per active file through
  `editor.gitBaselines.get`. File switches finish the visible Monaco open before
  issuing an immediate non-awaited request; returned disk/HEAD payloads bind
  only when their path remains active. Diff children hide vertical scrollbar
  chrome and retain automatic 10-pixel horizontal scrollbars.

## Code TE2 Standalone Terminal

- `app/apps/terminal` supports only
  `shellspec/node_terminal_stream.yaml`; the Python and native terminal
  shellspecs were removed and dead shells are not reopened.
- The persistent Node worker owns `node-pty`, `xterm-headless`, 5,000 rows of
  parsed scrollback, sequence assignment, and `SerializeAddon` checkpoints.
  Reconnect attaches serialize at sequence N, then releases only output newer
  than N; historical FWS log tails are not a terminal-state source.
- Browser traffic at `/ws/app/terminal/terminal?codec=msgpack-v1` is strict
  binary MessagePack with one object per WebSocket frame. Framework-Shell pipe
  traffic is `uint32` big-endian length-prefixed MessagePack. Python uses
  `msgspec.msgpack`; Node/browser use `@msgpack/msgpack`; there is no JSON,
  base64, or alternate shell-codec fallback.
- `xterm-headless@5.3.0` and `xterm-addon-serialize@0.11.0` intentionally match
  the vendored browser `xterm@5.3.0`. The Terminal Python backend atomically
  bootstraps its locked production Node dependencies under
  `$XDG_DATA_HOME/te2/node_runtime/terminal`. Both browser terminal surfaces
  load one shared `xterm@5.3.0` asset from `app/static/vendor/xterm/`; its
  readable source fork is `worktrees/xterm-te2` on branch `te2-android-ime`
  based on upstream tag `5.3.0`. Android uses a detached cumulative textarea
  transaction, suppresses xterm's composition overlay, and emits only
  current-transaction suffix corrections through xterm's `onData` event.

## TE2 Console And CLI

- Framework-owned console runtime at `/te2_console` namespace on path
  `/te2_console_ws/socket.io`, backed by `app/te2_console_runtime.py` and mounted
  by `app/te2_runtime_mounts.py`. Transcript at
  `~/.cache/app_server/te2_console_log.jsonl`. Event protocol: `console:register`,
  `console:log`, `console:eval`, `console:evalResult`, `console:evalCancel`,
  `console:replay`, `console:clear`.
- The browser `console_bridge.js` is bundled into `host.js` (source at
  `main_page/frontend/console_bridge.js`). It monkey-patches `console.*`,
  registers with `workerLabel` plus optional `uniquePerWindow: true`, and handles
  `console:eval` with `Promise.race` timeout (`Python timeout + 2s` buffer) and
  `console:evalCancel` rejection. Disconnect rejects all pending evals. `_serializeArg(undefined)`
  returns `null` rather than the string `"undefined"`.
- Python runtime passes `timeoutSeconds` in the `console:eval` payload and emits
  `console:evalCancel` to the worker room on `TimeoutError`. Late results are
  logged, not silently dropped.
- `te2 console` CLI subcommands: `list-workers` (connects and lists live
  workers), `eval --worker <id> [--code "..."]` (reads stdin if `--code` omitted)
  with `--timeout`, `--url` options, `tail [--worker] [--limit] [--level]`, and
  `search "query" [--worker] [--limit] [--level]`. Tail and search read the
  JSONL transcript directly; list-workers and eval require a running framework.

## Build And Publication

- Python package metadata and CLI entrypoints live in `pyproject.toml`; runtime
  dependencies live in `requirements.txt`. Framework releases synchronize
  `pyproject.toml`, the Rust server crate, code TE2 `static/version.txt`, the
  App Launcher manifest, every active built-in app manifest, and versioned
  frontend asset URLs. The shippable Electron desktop package participates in
  the same release version. Dependency and protocol-schema versions are
  independent.
- Code TE2 frontend changes require `npm run typecheck` and `node build.mjs` in
  `app/apps/file_editor_cm6` before handoff. Code TE2 has one browser build
  output: `static/dist/host.js`. The inline Monaco runtime and editor
  application are statically bundled into that host; do not restore a standalone
  Monaco bootstrap request or `static/dist/editor.js`.
- Code TE2's canonical `tsconfig.json` is shared by TypeScript 5.9 and TSGo 7
  and intentionally has no `baseUrl`; project-local imports are relative, while
  browser-root vendor imports use explicit `paths`. Vendored `vscode-textmate`
  9.3.2 and `vscode-oniguruma` 1.7.0 retain their exact runtime bundles plus
  their package-declared upstream type files.
- Android bundled assets are a separate publication path. Do not publish or
  modify Android assets unless that scope is explicitly approved. Rust
  `/api/editor_assets_bundle` builds each OTA ZIP with
  `Cache-Control: no-store`; do not restore version-only ZIP caching.

## Android Client

- GeckoView in Android `:app` is the primary renderer. Removed system WebView is
  not a fallback. Isolated `:cefrium` evaluates Cefrium 0.6.3; see
  `docs/apps/code_cm6/CODE_TE2.md` §42.
- GeckoView pinned to `144.0.20251027123126` for 16 KB page compatibility.
  Build tuple: Gradle 8.11.1, AGP 8.9.1, Kotlin 2.2.10, compileSdk 36,
  targetSdk 34. APK audits: arm64 Gecko `PT_LOAD` alignment `0x4000` and
  `zipalign -c -P 16 -v 4`.
- R8 minification must retain msgpack-core `MessageBufferU` and
  `MessageBufferBE`; suppress `sun.nio.ch.DirectBuffer` reference.
- `MainActivity` is locked to `sensorPortrait`. Settings are local
  `SharedPreferences`; do not read/write framework settings APIs. `UiIpcClient`
  uses websocket-only strict `msgpack-v1` on `/ui_ipc`; native `/te2_console`
  retains JSON event payloads.
- Gecko runtime details are small enough here: secure-context allowlist uses the
  configured `frameworkHost`; selection delegate preserves native Cut/Copy/Paste;
  APZ remains enabled while zoom is disabled; declared static interception is
  fail-closed and never redirects top-level framework documents.
- Asset publication is monotonic. Canonical launcher source is
  `app/android_shell/`; `bundle_gecko_assets.sh` consumes
  `app/android_editor_assets_bundle.json`; do not restore a second asset list.
  `gv_native` pages do not use the PWA Service Worker.

  43.1.1, Ozone/Wayland). GTK 4/WebKitGTK 6 in `desktop_client/ui.py` is a
  behavioral reference only. No `desktop_client/electrobun_spike/` directory

## Shared Modal Architecture

- Async `teUI.dialog` replaces browser `alert`/`confirm`/`prompt`. Browser and
  Android stay inline; Electron uses portable IPC child windows plus stateful
  same-origin `about:blank` portal adoption. `te_dialog.mjs` owns the portable
  contract; `te_modal_surface_portal.mjs` owns Electron stateful adoption.
- Keep CM6 JSON fields in Run Profiles and Settings. Code TE2 reusable modal UI
  components live under `main_page/frontend/ui/modal-kit/`. Deep modal details
  belong in `docs/apps/native-js-modal-plan-tracker/`, not repo memory.
