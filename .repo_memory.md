## Repository Safety And Source Ownership

- **IMPORTANT — launcher source names are misleading.**
  `desktop_client/android_shell/` is Electron-only launcher/settings source;
  its `android_shell` name is historical and does not make it shared with
  Android. `app/android_shell/` is the canonical GeckoView/Cefrium launcher
  source. `android/app/src/main/assets/editor_static/android-shell/` is bundled
  APK output. Trace the materialization path before editing or validating and
  never infer source ownership from the directory name.
- **IMPORTANT — native clients own their frontend assets.** Electron, GeckoView
  and Cefrium do not load Code TE2 UI bundles from the framework server. Their
  loopback/relay URL provides a stable origin and backend/proxy access; it is not
  frontend asset authority. After a frontend build, explicitly run that client's
  OTA/asset-update method (or bundle the new assets into its package/APK) before
  live validation. Page reloads only reload the client copy already installed and
  cannot pick up a newly built server-worktree bundle. Verify the client asset
  version/update result before interpreting any native-client frontend test.
- Follow `AGENTS.md` for approval, ownership and validation. Preserve unrelated
  edits, drafts and untracked files. Android changes need explicit scope.
- Never restart the shared TE2 runtime without approval. The known Ferrous
  cross-manager defect means `fws down` / `fws terminate` may kill the framework;
  use framework HTTP/Socket lifecycle endpoints for approved worker refreshes.
- Use `$TMPDIR` or a named workspace scratch directory, not hard-coded `/tmp`.
  Search source first; `.rgignore` excludes generated/vendor/worktree noise.
- Nested repositories are independent status/commit scopes. Root pytest excludes
  `worktrees/` to avoid collisions with their own top-level `tests` packages.
- Generated bundles, vendor publication and Android asset copies are outputs,
  not editable source. Validate nested projects from their repository roots.
- Keep this file concise and synchronized with technical documentation; remove
  superseded claims rather than accumulating progress reports or to-do lists.

## Framework Runtime

- Rust under `framework/rust/` is framework authority. `te2` / `te2-rust` enter
  through `app/cli/run_rust_framework.py` and the framework bootstrap, which
  selects the fingerprinted binary and starts the Python console/MCP bridge.
- Python remains for bootstrap/CLI, manifests/scaffolding, console/MCP, pipe
  support and app workers. Do not recreate the retired Python framework,
  supervisor, generic-extension backends, lifecycle or duplicate Git provider.
- Rust owns filesystem/Git/search, settings/state/bookmarks, app lifecycle,
  proxying and shell orchestration. Routine requests do not rediscover FWS
  metadata or scan `/proc`; explicit reconciliation owns discovery.
- Multi-threaded Tokio and bounded per-worker writer queues separate dispatch
  from blocking pipe writes. Queue saturation is explicit, not an event-loop wait.
- `app.libs.jobs` is core-only; no global `/api/jobs` or FastAPI/SSE router.
  Runtime, queue and retained-Python details: `CODE_TE2.md:4008` (§47).

- Runtime diagnostics startup opt-in uses `--runtime-debug` / `TE2_RUNTIME_DEBUG`;
  `--no-runtime-debug` overrides inheritance. Rust launch overrides manifest values.
  Status/eval use bounded live-loop dispatch; profiling remains separate.
  Shared writes serialize; duplicate replies cannot block
  stdin, and ordinary app dispatch stays unchanged (CODE_TE2.md §47).
- Rust debug status routes use exact app/shell/bridge-instance identity, one pending
  call and existing pipe I/O; timeout/disconnect cleanup never retries execution.
  CLI `te2 framework` and MCP share credential-protected Rust HTTP routes; MCP
  requires an explicit credential. Trusted eval is not sandboxed (CODE_TE2.md §47).
- WBA `wba-status/wba-eval` CLI and MCP reuse that authenticated Python route then
  its MessagePack pipe; exact child shell/process identity, no browser/HTTP eval.
  Live JS probes and bounded completion tracing: CODE_TE2.md, WBA Live Runtime Evaluation.
- Runtime-debug traces early Python imports/listener, Rust spawn/readiness and
  updated app-shell gate/init; clocks differ and init is not browser paint (§47).
- Lightweight service packages avoid eager re-exports. Run-profile projections
  reuse off-loop config reads per broadcast; no persistent cache (CODE_TE2.md §50).

- Runtime-debug shared proxy timing distinguishes WBA route arrival from upstream
  handshakes; bounded markers and closed-upstream regression test: CODE_TE2.md §50.
- Editor WBA sockets use `autoConnect: false` until the existing editor-lane
  adapter-ready snapshot/event; Monaco and document loading stay independent (§50).
- Networked app workers own paired async start/stop hooks outside ASGI lifespan;
  Code TE2 project initialization and eager intelligence use these hooks. Same
  process/loop; pipe-only mode unchanged. Cleanup contracts: CODE_TE2.md §50.
- App-worker serving readiness is released at Uvicorn's confirmed bound-listener
  boundary, not by a fixed lifespan delay. The asynchronous framework POST remains
  lifecycle-owned, so page release tracks the earliest real HTTP availability.
- Code TE2 opts into early intelligence bootstrap; only backend assembly moves
  off-loop. WBA attachment waits for code-server and app fact readiness. Contract:
  CODE_TE2.md §50, Early Intelligence Preparation And Backend Assembly.
- Framework/app-worker and WBA stdio pipes use concatenated MessagePack maps
  (32 MiB frame bound); upgrade both peers together. WBA stdout has typed records;
  Terminal log-framing remains pending. Details: CODE_TE2.md §50, Framework Pipe Codec.

- Native editor-services pipe audit: framework PipeEnvelope and WBA typed
  reply/push records are distinct MessagePack contracts. Ferrous binary writes
  use `write_to_pipe_blocking(&[u8])`, not string-based convenience methods.
  Native byte-subscription overflow removes the subscriber; protocol migration
  must fail a gapped stream, not silently resume it. Cross-process live-handle
  ownership is not established by API availability. See
  `docs/apps/client_runtime_polish/PIPE_BOUNDARY_INVENTORY.md`.

- `app.libs.pipe_transport.EnvelopeTransport` is the outbound framework-pipe
  seam; the stdio adapter owns encoding/write/flush while `pipe_runtime` retains
  correlation, identity, notifications, dispatch and writer serialization.
  Configure is setup-only; close releases waiters without closing borrowed stdout
  or retracting an in-flight write. Inbound decode/debug admission remains in
  `app_worker`; no native dependency elimination is implied.

- `pipe_inbound.InboundEnvelopeRouter` routes already-validated envelopes via
  injected runtime/debug callbacks without queues or retries. Ordinary dispatch
  stays synchronous; `app_worker` retains framing/schema checks and stream-close
  cleanup, while RuntimeDebugPipe retains bounded opt-in admission/loop handoff.

- Code TE2's ordinary `te2_pipe_dispatch` currently returns None; real editor
  services use their socket lanes. A pipe-only native harness proves handoff,
  not full editor migration or startup savings. Structural `pipe_dto` imports
  retain msgspec, but `pipe_protocol` aliases and
  lazy codec entrypoints no longer load messagepack_stream/msgpack. The Python
  wire path still loads those codecs; native handoff proposal:
  `docs/apps/client_runtime_polish/NATIVE_WORKER_HANDOFF.md`.

- `framework/native_editor_worker/` remains an independent Cargo workspace.
  Code TE2's branch shellspec now selects its `code-te2-worker` binary; the
  pipe-only fixture executable remains separate. Real domain handlers run on one
  Python asyncio thread, with independent framework reply delivery. Hyper and
  Socketioxide own the server transport; lock Engineioxide at 0.17.7 or later
  for correct binary waiting-poll packet separators. Build/wheel integration and
  live device parity remain separate gates. See its README.md.

- Native prototype reader completion must publish error/EOF state and release
  pending callers before dropping the application-queue sender. Sender-drop is
  observable completion; reversing this order can turn truncated input into a
  successful process exit. Deterministic ordering and repeated EOF tests cover it.

- Native editor-services destination: finish the Rust-owned I/O perimeter, remove
  displaced external Python imports, then compile the cohesive local Python
  domain graph with mypyc. Keep msgspec until that late stage has tested
  replacements for all codec/Struct/runtime-validation uses; compilation alone
  does not replace validation. Domain authority and worker isolation remain.
  Sequencing and evidence gates: client_runtime_polish/PLAN.md §6.

- Code TE2 declares manifest `readiness_support: "pipe"`: after domain startup
  and listener bind, its native worker emits `app.readiness` on the existing
  MessagePack stdout pipe. The framework validates the pipe-owned current shell,
  resets readiness for new shells, and rejects HTTP readiness updates for that
  mode. No shell-probe fallback. Catalogs retain boolean readiness support for
  clients; boolean callback apps (including ALS) remain unchanged. Rebuild both
  framework and native worker together; old frameworks ignore the notification.

- The independent Code TE2 native worker uses a worker-local Ferrous manager for
  WBA/code-server through `native_shells.py` and PyO3, retaining existing shellspecs
  and domain readiness/correlation. WBA byte transport remains Ferrous-owned;
  one native read survives Python timeout, and code-server stdout drains in Rust
  after readiness. Persisted metadata is not live pipe ownership. Exact PID-tree
  termination avoids process-group killing. FWS observation transport is now
  Rust-owned, with Python retaining domain handlers. See
  CODE_TE2.md, Native Intelligence Child Ownership.

- Run-profile/page-preview/watchexec management also uses the worker-local
  Ferrous adapter. Profile/preview output readiness consumes bounded live pipe
  bytes then switches to native log draining; failed readiness reaps the exact
  child. Watchexec binary chunks use bounded newline framing and existing Python
  event policy, with serialized start/stop/project replacement. Profile facts,
  proxy publication and FWS observation ownership are unchanged.

- Drawer launch/input/resize/close now use the worker-local Ferrous manager,
  pinned to native-PTY revision `f7ce068`. Controlling-terminal sessions and
  log-before-event publication are native. Owned exited removal follows exact
  tree shutdown and drainer stop; foreign persisted PTYs are not adopted.
  Rust owns bounded snapshot log readers; lazy Pyte and checkpoint/delta policy
  remain Python. The Rust FWS observer supplies wakeups. See
  CODE_TE2.md, Native Intelligence Child Ownership.

- `native_fws.py` consumes a bounded Rust observer (256 events / 8 MiB tree budget, 16 pending requests). Connection generations fence replies; disconnect/overflow rejects pending requests and reconnects for a snapshot before serial event replay. An ACK is not a revision fence: retain queued lifecycle events. Terminal `fws.logs.open` uses `projection: true` to avoid full history transfer; Rust raw-log reads remain authoritative. No Python Socket.IO fallback. See CODE_TE2.md, Native FWS Observation.

- Native `wba_codec.rs` owns bounded WBA control-pipe MessagePack decode/encode
  through `wba_pipe_codec.py`, with one decoder per stdout subscription. Python
  retains serialized writes, JSON-RPC correlation, push dispatch and domain
  validation; direct WBA sockets are unchanged. The interpreted codec is a
  tests/tools reference, not a native-error retry.

- Code TE2's native worker has no Python HTTP serving-readiness callback; its
  pipe readiness remains authoritative. Code Server's urllib.request import is
  deferred until an actual download, and the orphaned no-client draft HTTP POST
  is removed. Connected Explorer draft publication stays local. A fresh
  main/socket-gateway import omits urllib.request; no startup speedup is claimed.

- Mypyc 2.3.0 can type-check a large startup-reachable Code TE2 group, but a
  shared-library build is not runtime parity: compiled `DraftIndexSidecar`
  exposes its mutable `ClassVar` cache to `dataclasses`, and other local modules
  hit async-generator/coroutine deletion or builtin-exception inheritance
  limits. Direct `object` annotations in compiled DTO classes can fail at import;
  a local `TypeAlias = object` preserves the type and avoids that lookup failure.
  A compiled `@runtime_checkable` Protocol can also lose Protocol identity.
  Keep such modules interpreted or adapt them with behavior tests before any
  native-worker switch; evidence: `client_runtime_polish/PLAN.md` §5.

- Native worker experiments opt into a matching mypyc manifest/lib group with
  `CODE_TE2_MYPYC_DIR`; the experimental shellspec selects `.codex-scratch/mypyc-active`.
  Missing artifacts fail closed; no automatic build or interpreted fallback.
  Keep msgspec Struct schema modules interpreted until runtime annotation parity
  is proven, not their ordinary codec consumers. Developer overlays link source
  resources beside compiled modules; this is not wheel packaging. The 134-module
  desktop group passes isolated worker tests; device/live parity remains a separate
  gate. See native-worker README and client_runtime_polish/PLAN.md §6.

- In mypyc code, avoid assigning heterogeneous `asyncio.gather` results: its
  runtime list can conflict with tuple annotations. Preserve concurrency by
  awaiting the group then reading typed task results; discard unused group
  returns directly. Reader cleanup must reach native token release. CPython
  3.14 shield may report an expected cancelled-reader error even after cleanup
  retrieves it; distinguish that report from failed release (PLAN.md §6).

- The manifest `frontend_preparation` opt-in must survive Rust's explicit app/bootstrap and catalog payload projections. Dropping it silently disables local preparation and early splash reveal even for an already-ready worker. Ready snapshot plus local layout completion releases opted-in pages; full Monaco/content/sidebar initialization is not that visibility gate.

## Framework Assets, Roots And Exposure

- Rust serves shell assets from `app/templates/` and `app/static/`; built-ins
  are in `app/apps/`, user app source in `~/.local/share/te2/apps`.
- Manifests own catalog/readiness contracts. App-shell startup consumes one
  app-scoped `/api/apps/events?app_id=...` SSE stream, not serialized boot GETs.
- `TE2_*_HOME` values are final roots; otherwise XDG plus `/te2` applies.
  `$TE2_DATA_HOME/app_state/<app_id>` is state; `apps/<app_id>` is source.
- Legacy migration is an explicit stopped-framework, dry-run-first command,
  never startup recovery. Published fonts are the four supported WOFF2 faces.
- Loopback is default. `--broadcast` resolves once to bind hosts and exposure
  policy; outer Axum middleware protects HTTP, SSE, raw WS, Socket.IO and proxies.
- IP/CIDR policy checks peers; interface policy checks local destinations.
  Public bind addresses never replace loopback `TE_FRAMEWORK_URL` for workers.
- Exact roots, migration, readiness and network rules:
  `CODE_TE2.md:4008` (§47), `CODE_TE2.md:4057` (Network Exposure).

## RPC And Event Boundaries

- Surfaces use their own lanes: editor `/rpc/editor`, Explorer `/rpc/explorer`,
  host `/ui_ipc`, sidebar `/sidebar_ipc`, drawer `/terminal`.
- Python namespaces share `/api/app/code_te2/socket.io`; direct editor/WBA
  uses `/api/app/code_te2/services/wba/socket.io`. Do not proxy intelligence
  through Python. Console uses `/te2_console_ws/socket.io`, `/te2_console`.
- Editor/Explorer/host/Sidebar app-worker connections currently try Engine.IO
  polling before WebSocket upgrade; WBA and terminal stay WebSocket-only. This
  experiment has no proven latency gain until live client A/B measurement.
- Editor, Explorer, host and WBA require strict `msgpack-v1`; no JSON fallback.
  Sidebar retains its established codec. Old full socket paths are aliases only.
- Requests emit only when connected; notifications are volatile. Disconnect
  rejects pending requests, clears buffered traffic, and reconnect reconstructs
  state. Do not enable Socket.IO recovery or queue stale editing traffic.
- Cross-surface intent goes frontend -> own backend -> target backend hook ->
  target notification. No private frontend-to-frontend lane shortcuts.
- Codec metadata is default-off via `CODE_TE2_RPC_CODEC_METRICS`. Python
  transport ingress validates `object` mappings rather than propagating Any.
- Transport/codec/ownership contracts: `CODE_TE2.md:188` (§0.6),
  `CODE_TE2.md:538` (§6), `CODE_TE2.md:625` (§6.5).

- Native PyO3 outbound structural conversion accepts both Python lists and tuples
  as MessagePack arrays, matching the prior codec. History dataclass `asdict`
  preserves tuple fields (refs, parents, pages); rejecting tuples silently loses
  those publications. Sets/arbitrary iterators remain unsupported. Coverage uses
  real History handlers over polling and WebSocket, not only generic RPC DTOs.

## Sidebar And Persistence

- Code TE2 data uses canonical data/config/runtime/cache partitions, not legacy
  CM6 roots. Preferences are config; drafts/sidecars are data; sockets runtime.
- Sidebar ledger v2 owns shared membership, stable slot identity and lifecycle;
  host-local presentation owns order, foreground and embedded/hidden/detached.
- Browser presentation is bounded origin/project Local Storage; Electron uses
  validated atomic config IPC; Android uses app-private storage partitioned by
  stable client, upstream origin and project. Random relay ports are not keys.
- Empty initial lists and WBA reset/disconnect snapshots are non-authoritative.
  Only complete authoritative snapshots or explicit removal prune membership.
  Inactive projects remain parked; no polling or grace-window recovery.
- Reconciliation filters by the host's current project. Backend activation replay
  cannot reveal a locally hidden view; explicit local user intent is required.
- Mentions/file opens require exact client, stable host and live presentation
  identity. Re-created hosts re-register; no global-active/broadcast fallback.
- Browser/Android Sidebar dock menus have one keyed DOM owner. Launcher taps and
  icon long-presses open once per gesture; the release click is consumed.
  Close all and kill bulk-removes the selected app's slots in the shared ledger,
  then invokes the existing app quit action. See `CODE_TE2.md` §44-45.
- ALS-RS sidebar traffic resolves injected `TE_FRAMEWORK_URL`, then `TE_PORT`,
  then standalone 8089, not its own 12459 listener. Reconnect registers its peer.
- Ownership, storage/migration, focus and exact-client routing:
  `CODE_TE2.md:3861` (§45), `CODE_TE2.md:3023` (§38).

- WBA `membershipComplete=false` marks progressive primary-view activation:
  Python upserts ready views without pruning missing ones. Persistent contributed
  view hide/order preferences survive absent live membership; rendering and
  mention/foreground routing still require live slots. Disposable panels retain
  removal semantics. Existing client-local stores remain authority; no backend
  preference-store migration or time-based expiry is planned.

- `persistence_io.py` provides byte reads/atomic writes and separate stdlib JSON
  conversion for preferences, persisted extension registry and intelligence state.
  Stores retain locks, schema/DTO policy, migration and distinct corruption rules;
  no cache, new durability guarantee or native JSON codec. Native worker startup
  installs Rust byte reads/atomic writes before domain imports; blocking I/O
  releases interpreter attachment but retains synchronous completion. Interpreted
  tools retain the reference implementation, never a native-failure retry path.
  JSON formatting, flock, hash-sensitive registry serialization and other
  filesystem consumers remain outside the native byte boundary.

## Search And Explorer Projection

- Rust `service.search` owns file/content search. Python search sessions adapt
  bounded cache/state; the frontend renders progressive events on its own lane.
- Name search projects inside the existing tree, preserves tree DOM/open state,
  expands hit ancestors and shallow-hydrates direct directory matches in one
  bounded `fs.listDirectories` request. No per-hit frontend listing RPCs.
- Backend directory-selection facts update all project clients before local
  dismissal. Sticky search controls retain their bound DOM/IME input.
  Sticky subtree limits use source directory border-box geometry, not estimates.
- Content search retains at most 700 logical hits. Multiple same-line matches
  are separate hits. Supersede, overlay close and project switch cancel sessions.
- Replace targets retained hits, not rendered rows; Show All/Select All expose
  them. Hidden-hit confirmation is separate from draft-discard consent.
- Mobile UA uses long-press/tap selection without checkbox DOM; file headers
  follow group-select/deselect semantics. Desktop uses checkboxes.
- By Contents file groups use one faint card outline around each single-line
  file header and its hits. Header controls never wrap; the path truncates while
  hit snippets retain their independent wrapping.
- By Changes emits its first verified diff before later candidate validation,
  then uses bounded ordered workers and independent Git handles for remaining
  previews. One emitter preserves tracked-first pagination/continuations. Python
  retains up to 700 objects; exact path facts avoid re-enumeration. Both search
  views expand early; By Changes reveals 40 more rows and retains them
  (`CODE_TE2.md:881`).
- Limits, edit identities, cancellation, progressive search, sticky projection:
  `CODE_TE2.md:726` (§6.6). Git comparisons: `CODE_TE2.md:1460` (§8).
- By Changes headers start collapsed with preview +/- counts, tail-clipped paths
  and filename-aware icons. Streaming retains local expansion; header toggles,
  row navigation and Restore remain independent (`CODE_TE2.md:881`). Expand All
  opens the current page's files/hunks/blinds; active literal filters reuse
  By Contents hit styling without replacing syntax/diff token spans.

- By Changes compact headers expose per-file Stage (+), never hunk staging, and
  Stage and commit all with an empty index, otherwise Commit selected. Both are
  HEAD-only; Restore keeps confirmation and uses an explicit historical label.
  The shared commit prompt rejects project/comparison changes before dispatch.
  SVG fe-btn remote actions reuse Git lanes; Fetch only updates remote refs,
  unlike Pull. History separates Fetch from its local Refresh control.

- By Changes streams tracked results first and defers untracked entries to the
  end of the same stable pagination order. Suppressed text bodies retain Git line
  statistics, including oversized tracked files; editor admission stays separate.
  Header totals cover retained tracked files with untracked additions separate;
  partial projections are labeled. Header-only MRU follows clicks/latest live delta.

- Explorer filename search has both a source-tree input and a separately created sticky-scope input. Mobile input attributes such as `autocapitalize=off` must be set on both; the sticky input can be the focused Android control even when the source input is correctly configured.

- By Changes staging badges use the existing project Git-status snapshot, refreshed on status publications even for retained row DOM. Fully staged files show `Staged` and a disabled checkmark; additional unstaged disk edits show `Staged + edits` and retain Stage. Diff-preview status alone is not index authority.

## Comparison And Guarded Edits

- One Explorer comparison ref drives tree/By Changes metadata, inline commit
  baselines and the far-left status drop-up. HEAD follows current Git facts;
  explicit history stays pinned. Disk mode disables autosave and skips Git reads.
- `GitDiffBaseChanged` owns selection invalidation. Independent latest-only
  projectors schedule reads without blocking the fact bus; matching selection
  revisions deduplicate snapshots without dropping worktree refreshes.
- Historical tree styles compare selected tree against disk; real HEAD/index
  status stays separate for warnings/actions. Actual-state warning icons appear
  only in historical mode and never become filename text.
- Historical stage/commit/reset are rejected by the backend. Restore writes into
  the current worktree, confirms drafts, offers path-scoped unstage and preserves
  the index. Never move HEAD or create a detached worktree for this view.
- Hunk Restore and Find/Replace operate on disk, regardless of autosave.
  Python owns expiring exact-client/project/revision consent and draft safety;
  Rust owns bounded SHA-256/exact-range guarded writes, not draft materialization.
- Reverse hunks come from canonical UTF-8 buffers/libgit2, not display rows.
  Failed/no-op writes retain drafts; newer drafts survive successful operations.
  Accepted mutations survive disconnect; uncertain writes are never retried.
- Guarded apply serializes same-root writes but cannot exclude arbitrary external
  writers between check and rename. Limits and index/draft semantics:
  `CODE_TE2.md:751` (Guarded Text-Edit Foundation), `CODE_TE2.md:828`
  (Search Replacement), `CODE_TE2.md:1460` (comparison/Restore).

- Editor reconnect snapshots include the selected comparison ref and revision;
  apply that fence before asynchronous model/baseline work so missed change
  events cannot strand the old ref. Duplicate baseline notification/RPC replies
  skip completed application only while the same diff editor and model pair
  remain mounted; sibling notification delivery is preserved.

## Source Control History

- Explorer History is summary-only: commit/ref graph, filenames and +/- counts.
  File clicks open immutable read-only historical diffs in the second editor.
  It is not WBA-backed and does not place document text in the graph.
- `src/explorer/history/vscode_scm/` contains literal attributed upstream SCM
  copies and pinned base-tree inputs, reproduced through explicit patches.
  Use its UPSTREAM.md, not a lookalike implementation or fake workbench services.
- Rust owns retained metadata revwalks, immutable first-parent file/blob reads,
  and ref/config/reflog watches. Python owns connection-local generations and
  bounded lazy statistics. Strict typed DTOs preserve captured ref/blob identity.
- Native sessions are exact pipe-owner/root/generation scoped. Lease expiry
  renews behind the same logical generation only when Rust snapshot identity and
  the replayed commit frontier match; otherwise the visible fallback refreshes.
  A project-local in-memory ledger restores expanded commit OIDs/page frontier
  across that real refresh and dies with the History surface. No polling,
  keepalive, persistent view state or historical-file intent replay is allowed.
- Metadata uses pure topological traversal with captured tips seeded newest-first;
  OID ordering or TIME traversal distorts branch continuity. Pinned current,
  upstream and base roles feed unchanged upstream lane colors.
- File statistics are independently bounded from preview admission. Partial totals
  remain partial, not falsely complete; binary/oversized preview states are explicit.
  File rows remain left-aligned and preserve full-bright basenames while a dimmed
  directory prefix clips from the repository/root side under width pressure.
- Frontend generations preserve row DOM, exact file indices, local selection,
  lazy expansion and single-flight early scroll prefetch. Fixed commit headers
  have the same compact shape on desktop and mobile. Mobile expanded cards and
  desktop hover panels share the full detail presentation and statistics without
  extra Git reads; localized timestamps live in their author byline, not the
  fixed header. Their short hash copies the full commit ID without activating
  the owning history row.
- Protocols, bounds, watches, upstream provenance and role resolution:
  `CODE_TE2.md:983` (§6.7).

## Historical Secondary Editor

- Backend secondary content state is distinct from working foreground and native
  presentation. File-open tickets are short-lived, bounded and single-use;
  authenticated secondary redemption validates retained project/session identity.
- Working/history kind changes reload only the secondary realm after command
  acknowledgement. Historical revisions abort/replace in place; duplicates reuse.
  Existing atomic persistence needs no additional save/flush, and membership stays.
- Historical boot loads basic/Monarch syntax only and allows the diff worker,
  not language services. Unique `te2-history:` models never enter WBA.
- Read-only controls reject Save/discard/mutation; navigation, selection, Find
  and Copy target the last focused diff side. No working-model fallback.
- Snapshot/live preferences project font/theme/line numbers/wrap through a safe
  allowlist. Theme requests are revision/abort-fenced; stale loads cannot publish.
- Theme picker metadata uses host RPC (`ui.host.themes.list`); Python projects
  only the preference-selected theme JSON via `editor.theme.selected` before
  working document models mount, with no catalog-wide frontend theme loading.
  Historical views fetch just their selected theme through the host lane.
  Monaco/TextMate styling is shared; see CODE_TE2.md §26.
- Editor HTTP assets are served by `framework/native_editor_worker/src/web.rs`;
  editor state has no web-framework imports. The old Python resource module is a
  parity fixture. Backend grammar RPC remains separate from HTTP `onig.wasm`.
- Main HTTP retains only health/resources; legacy read/state/diff/review and raw
  read/edit-tracker/debug sockets are removed, not their shared services.
