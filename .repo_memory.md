# TE2 Repository Memory

Operational orientation for `feature/code-te2-native-services`, not a task/release
log. Source wins. `CODE_TE2.md` means `docs/apps/code_te2/CODE_TE2.md`; use named
headings, not remembered line numbers. Read the relevant technical contract before editing.

## Workflow And Protected State

- Follow `AGENTS.md`: prompt approval, read-only investigation, concrete final
  plan approval, then only the approved changes. Preserve unrelated edits,
  drafts and untracked files. Android is read-only outside explicitly approved scope.
- Never restart/terminate the shared Rust TE2 framework without explicit approval.
  The recorded Ferrous cross-manager hazard means `fws down` / `fws terminate`
  must not be treated as safe app refreshes. Use the established framework
  lifecycle endpoints for an approved worker refresh; inspect exact live ownership.
- Reuse existing methods, backend hooks and UI conventions. Do not create
  parallel implementations or move durable authority into frontends.
- Use `$TMPDIR`, otherwise a named workspace scratch directory. Search source
  first; `.rgignore` hides generated/vendor/worktree noise. Inspect intended
  ignored paths explicitly. Bundled JS inspection stays stream-only.
- Generated bundles, APK assets and vendor publication are outputs, not editable
  source. Nested repositories have independent status/commit/build scopes.
  Preserve Cargo caches; root pytest excludes worktrees. Smoke commands stand alone.
- Preserve accepted executable/mypyc groups in
  `.release/mypyc-checkpoint-20260929/`; scratch cleanup must not delete them.
  Package integration requires resources and matching ABI/provenance, not
  developer symlinks or absolute manifest paths.
- Keep memory concise. Put algorithms, incident history, measurements and
  release evidence in technical docs. Do not delete a user instruction or repo
  rule: retain a short guard here and its full contract at the referenced destination.

## Native Client Assets — Check Before Live Validation

- **Launcher ownership:** `desktop_client/android_shell/` is Electron-only;
  `app/android_shell/` is Android source. Android
  `assets/editor_static/android-shell/` is generated APK output. Trace
  materialization; directory naming does not make these interchangeable.
- **Building server-worktree frontend bundles does not update an installed
  native client.** After frontend publication, explicitly run that client's
  OTA/asset updater or install a package/APK containing the new seed. Verify
  local asset version, update result and served content before testing.
  Reload alone reloads the installed copy. Do not blame cache without evidence.
- Android uses APK seed/OTA materialization into `filesDir/editor_static`.
  Declared missing assets fail locally; they do not fall through to the server.
  The relay blocks exact `/sw.js`, not every Service Worker. Use scoped cleanup.
  Native Settings schedules the existing renderer-owned single-flight OTA flow.
- Electron uses its inventory-approved installed desktop asset tree. **Current
  exception:** local serving is enabled only when required files are present;
  an incomplete tree disables interception and requests can proxy upstream.
  With local serving enabled, a missing mapped file returns 404. Verify status
  and provenance rather than assuming every relay response is local.
- Electron update activation refreshes relay asset state, clears framework
  partition HTTP/generated-code caches, and reloads requested active views.
  Android seeding skips a matching or newer local version; a same-version stale
  seed is not repaired by reload. Use the updater's established force path when needed.
- Relays provide browser origins and backend access, not proof of fresh assets.
  Dynamic framework/API/socket traffic remains upstream. Configured upstream
  identity is distinct from the random browser relay origin.
- Publication order: changed Monaco ESM →
  `node scripts/build_monaco_bootstrap_bundle.mjs` → Code TE2 `node build.mjs`
  → approved client OTA/package publication. Monaco bootstrap is embedded in
  `host.js`; rebuilding bootstrap alone leaves host behavior unchanged.
- Details: CODE_TE2.md, **Native Client Asset Publication And Validation**,
  **Android Static Asset Bundling**, **Native clients and secondary-editor integration**, **Monaco
  asset pipeline**; `android/cefrium/README.md`.

## Cefrium ADB / CDP Access

- Use TE2 console for page state, the **native Cefrium console worker** for
  Android commands, and CDP for Chromium page/worker inspection. Discover exact
  worker IDs; labels are not unique. Capture evidence before reloading the failing
  page or restarting anything.
- Discover the device: `adb devices -l`; discover workers:
  `te2 console list-workers`. Send this to the native Cefrium console worker:
  `{"jsonrpc":"2.0","method":"android.devTools.state.get","params":{}}`.
  Read `bridgePort`, `controlConnected`, `activeTargetId` and inspector readiness.
  Ports, targets and sessions are live values; rediscover after restart.
- Forward that exact device port:
  `adb -s "$DEVICE" forward tcp:0 tcp:"$DEVICE_CDP_PORT"`.
  Record its returned local port. Inspect `/json/list` and `/json/version` at
  `http://127.0.0.1:$LOCAL_PORT`; choose by live type/URL/parent relationship.
  Connect to the discovered `webSocketDebuggerUrl`, rebasing its authority to
  the forwarded host port if needed. Keep this control interface loopback-only.
- Correlate CDP replies by request ID with bounded timeouts; unsolicited events
  can precede replies. Inspect first. `Runtime.runIfWaitingForDebugger` resumes
  execution and needs explicit approval for the exact target; never make it
  a blanket startup workaround.
- Close probe sockets, terminate probe workers/revoke Blob URLs, and remove only
  this forwarding: `adb -s "$DEVICE" forward --remove tcp:"$LOCAL_PORT"`.
  Never use `--remove-all`.
- Preserve the Inspector's flattened child-session subtree before native monitor
  dispatch, including attachment/context events and child `sessionId` values.
  Swallowing these strands debugger-paused workers. Native monitor ownership is
  separate; do not hide the defect by disabling debugger waits.
- Full runbook: CODE_TE2.md, **Cefrium CDP-over-ADB investigation workflow**.
  Incident evidence: `docs/apps/client_runtime_polish/PLAN.md`. Do not attribute
  renderer failures to old tombstones; correlate current device/page evidence.

## Branch Runtime And Build Authority

- Rust `framework/rust/` is framework authority; `te2` / `te2-rust` enter through
  `app/cli/run_rust_framework.py` and bootstrap. Python remains CLI/bootstrap,
  console/MCP, helpers and app domain code. Do not recreate retired Python
  framework/supervisor/lifecycle/generic-extension/Git implementations.
- Rust owns framework FS/Git/search, settings/state/bookmarks, proxying,
  app lifecycle and shell orchestration. Routine requests do not rediscover
  FWS metadata or scan `/proc`; explicit reconciliation owns discovery.
- **This branch launches `framework/native_editor_worker/target/release/code-te2-worker`.**
  Hyper/Socketioxide owns HTTP/sockets and Rust owns framework MessagePack framing;
  PyO3 hosts existing Python domain handlers on their asyncio thread.
  Python namespace helpers are local adapters, not Python Socket.IO servers.
- Code TE2 declares `readiness_support: "pipe"`: readiness follows domain startup
  and bound listener via `app.readiness` on the current worker pipe. No HTTP
  readiness update or shell-probe substitute for this mode. Rebuild framework and
  native worker together for contract changes. Other apps can retain callback readiness.
- Native worker is an independent Cargo workspace. Source builds require matching
  regular system CPython/venv ABI. The branch shellspec selects
  `CODE_TE2_MYPYC_DIR=.codex-scratch/mypyc-active`; missing/mismatched artifacts
  fail, with no automatic build or silent interpreted fallback.
  Wheel/bootstrap integration is not implemented; do not publish as integrated release.
- Worker-local Ferrous owns migrated intelligence/profile/preview/watcher/drawer
  children; exact PID-tree shutdown, live pipe ownership and drainer cleanup matter.
  Rust owns outbound FWS observation; Python retains domain facts/policy.
  Persisted metadata does not grant live pipes; no Python networking failure fallback.
- Framework and WBA control pipes have distinct bounded MessagePack contracts.
  Upgrade matched peers; stdout is protocol-only. Native failures/gapped streams
  must not retry through reference codecs. Timeouts/disconnects do not retry mutations.
- Runtime debug/eval is explicit opt-in, credential/identity protected and not
  sandboxed. Use established CLI/MCP routes; profiling is separate.
- Build instructions and detailed rules: `framework/native_editor_worker/README.md`;
  CODE_TE2.md, **Worker Transport Exports**, **Native Intelligence Child Ownership**,
  **Native FWS Observation**, **Native Domain Compilation And Artifact Preservation**,
  **Framework Runtime And Deployment Reference**;
  `docs/apps/client_runtime_polish/PIPE_BOUNDARY_INVENTORY.md` and `PLAN.md`.

## Roots, Identity And RPC Boundaries

- `TE2_*_HOME` values are final roots; otherwise XDG plus `/te2` applies.
  Data/config/runtime/cache have distinct purposes. `app_state/<app_id>` is state;
  `apps/<app_id>` is app source. Legacy migration is explicit, stopped-framework
  and dry-run-first, never startup recovery.
- Loopback is default; `--broadcast` resolves bind/exposure policy once. Peer
  IP/CIDR and local-destination interface rules differ. Public bind addresses
  never replace loopback `TE_FRAMEWORK_URL` for workers.
- Code TE2 source is `app/apps/code_te2`: `main.py` domain assembly, `main.ts`
  host, `monaco_editor/m_editor_app.ts` editor. Host UI: `main_page/frontend/`;
  Explorer: `src/explorer/` and `explorer/`; actions: `host/`; IPC: `ui_ipc/`;
  WBA: `workbench_protocol_proxy/`. Generate canonical `code_te2` identities;
  legacy aliases are migration contracts, never separate workers/catalog entries.
- Sidecar recents own shared membership/drafts; stable `clientInstanceId` owns
  reconnectable foreground and role. `windowId` is presentation metadata;
  `last_file` is one-time migration seed. Frontend paths are projections.
- Editor `/rpc/editor`, Explorer `/rpc/explorer`, host `/ui_ipc`, Sidebar
  `/sidebar_ipc`, drawer `/terminal` share `/api/app/code_te2/socket.io`.
  Direct intelligence: `/api/app/code_te2/services/wba/socket.io`, `/wba`.
  Console: `/te2_console_ws/socket.io`, `/te2_console`. Never relay intelligence via Python.
- Current app-worker editor/Explorer/host/Sidebar clients try polling then
  WebSocket; WBA/terminal are WebSocket-only. No proven latency improvement is
  implied. Editor/Explorer/host/WBA use strict `msgpack-v1`; Sidebar retains its codec.
- Requests require connection; notifications are volatile. Disconnect rejects
  pending requests/clears buffers; reconnect reconstructs authoritative state.
  No Socket.IO recovery, stale editing queue or uncertain mutation replay.
- Cross-surface intent: frontend → own backend → target hook → target notification.
  Exact-client routing has no global-active/broadcast fallback.

- Production app-intent foundation: `app_intent_pipe.rs` registers exact owned
  worker pipes independently of runtime-debug. `app.open` reuses lifecycle URL
  authority; `app.intent.dispatch` forwards allowlisted `app.intent.deliver`
  requests with framework-derived source identity, bounded correlation and no
  mutation replay. Native `AppIntentPipe` schedules bounded requests on the domain
  loop; `document.open` reuses the Sidebar live-client/active-slot/app checks and
  requires the current presentation ID. Other intents/UI integration are pending;
  no arbitrary method dispatch or fabricated socket session. Contract:
  `docs/apps/sidebar_app_intents/PLAN.md`, **Production Pipe Foundation**.

## Domain Guards To Read Before Editing

- **Sidebar:** shared ledger owns membership/lifecycle; client stores own order,
  visibility and presentation. Random relay origins are not persistence keys.
  Empty/incomplete activation/reset snapshots do not prune membership. Preserve
  parked projects/hidden views; only explicit user intent reveals hidden views.
  No expiry/polling/new backend preference tier. Read CODE_TE2.md,
  **Sidebar Membership And Host Presentation Ownership**, **UI VSIX Webviews And Editor Contributions**.
- **Search/Git/History:** retained hits, actual index state and selected comparison
  are different authorities. Historical stage/commit/reset are rejected; Restore
  writes current worktree with draft consent and preserves index, never moves HEAD.
  Guarded edits are exact-client/project/revision/SHA/range scoped; uncertain
  accepted writes are not retried. History uses attributed upstream SCM copies;
  immutable historical models never enter WBA or allow Save/discard/mutation.
  Read **Search system**, **Source Control History Component Foundation**,
  **Secondary History Content State Foundation**, and comparison/Restore in CODE_TE2.md.
- **WBA:** logical documents are shared, facades exact-client; releasing one client
  must not release another's document. Visible open completion is separate from
  intelligence acknowledgement. Python diagnostics serve Explorer/Problems only;
  no editor nudges. Generic selector matching, no language-specific routing hacks.
  Read **WBA Logical Documents And Multi-File Extension Handling**,
  **Multi-provider language features**, **Diagnostics owner-keyed markers**.

- **First model:** backend-owned selected theme/grammar catalog and active grammar

- **UI/input:** authored Code TE2 controls use app-owned popup/listboxes, not native

## Native Lifecycle And Publication

- GeckoView remains primary; Cefrium is isolated. `PersistentNetworkService` owns
  Android relay/routes/UI IPC/console across activity recreation. Cold restore
  requires fresh route authority; route listeners and Inspector targets are separate.
  Do not duplicate service-owned transports in activities or persist routes as authority.
- Cefrium's standalone `android/cefrium` build uses its own JDK 25/SDK 37 setup;
  do not invoke it as a root Android subproject. Keep compile-only Window Extensions
  interface dependency, not the duplicate keep rule. Preserve renderer-specific
  input font safeguards; pinch policy is not universal page-scale suppression.
- Electron IPC/presentation and primary/secondary identities stay validated and
  distinct; existing native UI IPC reconnect owns route readiness. Exit stops only
  Electron's owned framework child, never an external/remote framework.
- Frontend checks: `npm run typecheck`, `node build.mjs` in `app/apps/code_te2`.
  Output is `static/dist/host.js`, not `editor.js`. Synchronize release-facing
  versions for native frontend contracts; build frontend before approved bundling.
  Check ≥2 GB free before Android builds; retain debug/release inspection isolation.
- Verified binary installs must not silently build/fall back to Cargo. Preserve
  checksum/features/ABI/provenance and accepted archives; no release-performance
  claim from isolated import or fixture tests. Consult **Build And Installation
  Contracts**, native-worker README and client-runtime `PLAN.md` before packaging.
