# TE2 Repository Memory

Operational orientation for `feature/code-te2-native-services`, not a task/release
log. Source wins. `CODE_TE2.md` means `docs/apps/code_te2/CODE_TE2.md`; use named
headings, not remembered line numbers. Read the relevant technical contract before editing.

## Workflow And Protected State

- Follow `AGENTS.md`: prompt approval, read-only investigation, concrete final
  plan approval, then only the approved changes. Preserve unrelated edits,
  drafts and untracked files. Android is read-only outside explicitly approved scope.
- Never restart/terminate the shared Rust TE2 framework without explicit approval.
  The recorded Ferrous cross-manager hazard means `fws down` / `fws terminate`
  must not be treated as safe app refreshes. Use the established framework
  lifecycle endpoints for an approved worker refresh; inspect exact live ownership.
- Reuse existing methods, backend hooks and UI conventions. Do not create
  parallel implementations or move durable authority into frontends.
- Use `$TMPDIR`, otherwise a named workspace scratch directory. Search source
  first; `.rgignore` hides generated/vendor/worktree noise. Inspect intended
  ignored paths explicitly. Bundled JS inspection stays stream-only.
- Generated bundles, APK assets and vendor publication are outputs, not editable
  source. Nested repositories have independent status/commit/build scopes.
  Preserve Cargo caches; root pytest excludes worktrees. Smoke commands stand alone.
- Preserve accepted executable/mypyc groups in
  `.release/mypyc-checkpoint-20260929/`; scratch cleanup must not delete them.
  Package integration requires resources and matching ABI/provenance, not
  developer symlinks or absolute manifest paths.
- Keep memory concise. Put algorithms, incident history, measurements and
  release evidence in technical docs. Do not delete a user instruction or repo
  rule: retain a short guard here and its full contract at the referenced destination.

## Native Client Assets — Check Before Live Validation

- **Launcher ownership:** `desktop_client/android_shell/` is Electron-only;
  `app/android_shell/` is Android source. Android
  `assets/editor_static/android-shell/` is generated APK output. Trace
  materialization; directory naming does not make these interchangeable.
- **Building server-worktree frontend bundles does not update an installed
  native client.** After frontend publication, explicitly run that client's
  OTA/asset updater or install a package/APK containing the new seed. Verify
  local asset version, update result and served content before testing.
  Reload alone reloads the installed copy. Do not blame cache without evidence.
- Android uses APK seed/OTA materialization into `filesDir/editor_static`.
  Declared missing assets fail locally; they do not fall through to the server.
  The relay blocks exact `/sw.js`, not every Service Worker. Use scoped cleanup.
  Native Settings schedules the existing renderer-owned single-flight OTA flow.
- Electron uses its inventory-approved installed desktop asset tree. **Current
  exception:** local serving is enabled only when required files are present;
  an incomplete tree disables interception and requests can proxy upstream.
  With local serving enabled, a missing mapped file returns 404. Verify status
  and provenance rather than assuming every relay response is local.
- Electron update activation refreshes relay asset state, clears framework
  partition HTTP/generated-code caches, and reloads requested active views.
  Android seeding skips a matching or newer local version; a same-version stale
  seed is not repaired by reload. Use the updater's established force path when needed.
- Relays provide browser origins and backend access, not proof of fresh assets.
  Dynamic framework/API/socket traffic remains upstream. Configured upstream
  identity is distinct from the random browser relay origin.
- Publication order: changed Monaco ESM →
  `node scripts/build_monaco_bootstrap_bundle.mjs` → Code TE2 `node build.mjs`
  → approved client OTA/package publication. Monaco bootstrap is embedded in
  `host.js`; rebuilding bootstrap alone leaves host behavior unchanged.
- Details: CODE_TE2.md, **Native Client Asset Publication And Validation**,
  **Android Static Asset Bundling**, **Native clients and secondary-editor integration**, **Monaco
  asset pipeline**; `android/cefrium/README.md`.

- Launcher catalog asset URLs must use the existing native framework-to-relay rewrite, including `icon_src` and `asset_base_url`. Android gateway normalization previously made icon URLs remote-absolute and bypassed packaged assets. Preserve genuinely external URLs; inventory-approved icon paths are served from the local client bundle. Launcher Code TE2 image is 40px inside its unchanged 52px container.

## Cefrium ADB / CDP Access

- Use TE2 console for page state, the **native Cefrium console worker** for
  Android commands, and CDP for Chromium page/worker inspection. Discover exact
  worker IDs; labels are not unique. Capture evidence before reloading the failing
  page or restarting anything.
- Discover the device: `adb devices -l`; discover workers:
  `te2 console list-workers`. Send this to the native Cefrium console worker:
  `{"jsonrpc":"2.0","method":"android.devTools.state.get","params":{}}`.
  Read `bridgePort`, `controlConnected`, `activeTargetId` and inspector readiness.
  Ports, targets and sessions are live values; rediscover after restart.
- Forward that exact device port:
  `adb -s "$DEVICE" forward tcp:0 tcp:"$DEVICE_CDP_PORT"`.
  Record its returned local port. Inspect `/json/list` and `/json/version` at
  `http://127.0.0.1:$LOCAL_PORT`; choose by live type/URL/parent relationship.
  Connect to the discovered `webSocketDebuggerUrl`, rebasing its authority to
  the forwarded host port if needed. Keep this control interface loopback-only.
- Correlate CDP replies by request ID with bounded timeouts; unsolicited events
  can precede replies. Inspect first. `Runtime.runIfWaitingForDebugger` resumes
  execution and needs explicit approval for the exact target; never make it
  a blanket startup workaround.
- Close probe sockets, terminate probe workers/revoke Blob URLs, and remove only
  this forwarding: `adb -s "$DEVICE" forward --remove tcp:"$LOCAL_PORT"`.
  Never use `--remove-all`.
- Preserve the Inspector's flattened child-session subtree before native monitor
  dispatch, including attachment/context events and child `sessionId` values.
  Swallowing these strands debugger-paused workers. Native monitor ownership is
  separate; do not hide the defect by disabling debugger waits.
- Full runbook: CODE_TE2.md, **Cefrium CDP-over-ADB investigation workflow**.
  Incident evidence: `docs/apps/client_runtime_polish/PLAN.md`. Do not attribute
  renderer failures to old tombstones; correlate current device/page evidence.

## Branch Runtime And Build Authority

- Rust `framework/rust/` is framework authority; `te2` / `te2-rust` enter through
  `app/cli/run_rust_framework.py` and bootstrap. Python remains CLI/bootstrap,
  console/MCP, helpers and app domain code. Do not recreate retired Python
  framework/supervisor/lifecycle/generic-extension/Git implementations.
- Rust owns framework FS/Git/search, settings/state/bookmarks, proxying,
  app lifecycle and shell orchestration. Routine requests do not rediscover
  FWS metadata or scan `/proc`; explicit reconciliation owns discovery.
- **This branch's shellspec launches the raw `CODE_TE2_WORKER_BIN` resolved by framework bootstrap.**
  Hyper/Socketioxide owns HTTP/sockets and Rust owns framework MessagePack framing;
  PyO3 hosts existing Python domain handlers on their asyncio thread.
  Python namespace helpers are local adapters, not Python Socket.IO servers.
- Code TE2 declares `readiness_support: "pipe"`: readiness follows domain startup
  and bound listener via `app.readiness` on the current worker pipe. No HTTP
  readiness update or shell-probe substitute for this mode. Rebuild framework and
  native worker together for contract changes. Other apps can retain callback readiness.
- Native worker is an independent Cargo workspace. Source builds require matching
  regular system CPython/venv ABI. The branch shellspec selects
  `CODE_TE2_MYPYC_DIR=.codex-scratch/mypyc-active`; missing/mismatched artifacts
  fail, with no automatic build or silent interpreted fallback.
  Source bootstrap now builds/publishes configured native executables; matched
  worker/domain wheel integration is not implemented. Do not publish as integrated release.
- Worker-local Ferrous owns migrated intelligence/profile/preview/watcher/drawer
  children; exact PID-tree shutdown, live pipe ownership and drainer cleanup matter.
  Rust owns outbound FWS observation; Python retains domain facts/policy.
  Persisted metadata does not grant live pipes; no Python networking failure fallback.
- Framework and WBA control pipes have distinct bounded MessagePack contracts.
  Upgrade matched peers; stdout is protocol-only. Native failures/gapped streams
  must not retry through reference codecs. Timeouts/disconnects do not retry mutations.
- Runtime debug/eval is explicit opt-in, credential/identity protected and not
  sandboxed. Use established CLI/MCP routes; profiling is separate.
- Build instructions and detailed rules: `framework/native_editor_worker/README.md`;
  CODE_TE2.md, **Worker Transport Exports**, **Native Intelligence Child Ownership**,
  **Native FWS Observation**, **Native Domain Compilation And Artifact Preservation**,
  **Framework Runtime And Deployment Reference**;
  `docs/apps/client_runtime_polish/PIPE_BOUNDARY_INVENTORY.md` and `PLAN.md`.

- Source edits to compiled-domain modules do not affect an existing mypyc group or a running worker. Rebuild/validate the selected matching-ABI group and restart the app worker through its approved lifecycle before live testing new exports; frontend OTA cannot fix a stale Python extension. Preserve the previous group when switching `mypyc-active`.

- Developer mypyc workflow now separates mutable ABI/toolchain/module-set-keyed build caches from validated library-only snapshots. `scripts/probe_code_te2_mypyc.py build --output <new-snapshot>` reuses intermediates and optional dedicated 512 MB ccache; missing ccache is reported, not silently required. Explicit `activate --snapshot` checks ABI/checksums and retains `mypyc-active-previous`; no process restart. `prune` is dry-run-first/managed-snapshots-only, retains newest two plus active/previous, and never cleans legacy experiments or release checkpoints. Consult native-worker README; do not point a worker at the mutable build cache.

- Matched native artifact installation remains planned (atomic executable/domain pairing and wheels pending): source bootstrap publishes the executable and the explicit mypyc entrypoint publishes domain snapshots under `TE2_CACHE_HOME/code_te2/build`. Wheels will own `app/release_runtime/code_te2/` with independent `bin/code-te2-worker`, ABI-matched domain libraries/resources and provenance. No scratch/target paths or developer links in packaged runtime. Binary installs must not fall back to Cargo/interpreted mode. Keep Rust/domain fingerprints independent. See native-worker README, **Planned installed artifact placement**, and client-runtime PLAN, **Code TE2 native artifact installation contract**.

- TE2 MCP FWS inspection uses the existing codec-aware inspector for both tails and queries; `lines` bounds the recent event window and `limit` caps query matches. Do not route inspection queries through raw UTF-8 search on MessagePack logs. Null `error`/`id`/`method` fields in pipe envelopes require value-aware classification. CLI and MCP may resolve different FWS environments; verify executable and package version. See `app/te2_mcp/README.md`.

- Editable mypyc build entrypoint: `python -B app/apps/code_te2/build_mypyc.py` reuses the existing compiler cache and publishes validated domain snapshots under resolved `TE2_CACHE_HOME/code_te2/build/mypyc-snapshots/<id>/lib`. It activates through the existing checkout selector only after a successful build, retaining the previous selection; `--no-activate` and read-only `--print-commands` are available. No Rust executable build, restart, or wheel integration. Shared-group header/module-set changes can invalidate most C objects: cache reuse is not a promise of incremental speedup.

- The preferred `app/apps/code_te2/build_mypyc.py` entrypoint now fails before build/inventory when `ccache` is absent from PATH. Explicit `--no-cache` or `NO_CACHE=1` permits a slower build and disables compiler caching for that invocation (retaining intermediates). The low-level probe remains available for diagnostics; no silent uncached fallback from the preferred wrapper.

- Framework bootstrap owns configured native Cargo builds via `app/native_worker_builds.json`: normal source startup and `--build-only` build/reuse independently, publishing under `TE2_CACHE_HOME/<app_id>/build/bin/<fingerprint>/<profile>`, with separate Cargo intermediates and invoking Python ABI in Code TE2's identity. Bootstrap exports `CODE_TE2_WORKER_BIN`; the shellspec launches the raw executable directly, not a wrapper. `--print-command` is non-mutating; `--force-build` includes workers. A newly launched framework must ingest this environment. Domain mypyc activation remains explicit, and binary-worker/domain wheel assembly is still pending (no Cargo fallback from a missing binary-release payload).

- Native worker shellspec rendering must inherit the complete server environment before applying the Ferrous child overlay and app launch overrides. The overlay alone omits bootstrap-selected `CODE_TE2_WORKER_BIN` and prevents spawning on desktop and Termux. The actual Code TE2 shellspec has regression coverage; spawn logs retain the full cause chain. Handoff fixes require rebuilding/restarting the framework server, not just the worker. See native-worker README, **Framework bootstrap-managed native executable (source installs)**.

## Roots, Identity And RPC Boundaries

- `TE2_*_HOME` values are final roots; otherwise XDG plus `/te2` applies.
  Data/config/runtime/cache have distinct purposes. `app_state/<app_id>` is state;
  `apps/<app_id>` is app source. Legacy migration is explicit, stopped-framework
  and dry-run-first, never startup recovery.
- Loopback is default; `--broadcast` resolves bind/exposure policy once. Peer
  IP/CIDR and local-destination interface rules differ. Public bind addresses
  never replace loopback `TE_FRAMEWORK_URL` for workers.
- Code TE2 source is `app/apps/code_te2`: `main.py` domain assembly, `main.ts`
  host, `monaco_editor/m_editor_app.ts` editor. Host UI: `main_page/frontend/`;
  Explorer: `src/explorer/` and `explorer/`; actions: `host/`; IPC: `ui_ipc/`;
  WBA: `workbench_protocol_proxy/`. Generate canonical `code_te2` identities;
  legacy aliases are migration contracts, never separate workers/catalog entries.
- Sidecar recents own shared membership/drafts; stable `clientInstanceId` owns
  reconnectable foreground and role. `windowId` is presentation metadata;
  `last_file` is one-time migration seed. Frontend paths are projections.
- Editor `/rpc/editor`, Explorer `/rpc/explorer`, host `/ui_ipc`, Sidebar
  `/sidebar_ipc`, drawer `/terminal` share `/api/app/code_te2/socket.io`.
  Direct intelligence: `/api/app/code_te2/services/wba/socket.io`, `/wba`.
  Console: `/te2_console_ws/socket.io`, `/te2_console`. Never relay intelligence via Python.
- Current app-worker editor/Explorer/host/Sidebar clients try polling then
  WebSocket; WBA/terminal are WebSocket-only. No proven latency improvement is
  implied. Editor/Explorer/host/WBA use strict `msgpack-v1`; Sidebar retains its codec.
- Requests require connection; notifications are volatile. Disconnect rejects
  pending requests/clears buffers; reconnect reconstructs authoritative state.
  No Socket.IO recovery, stale editing queue or uncertain mutation replay.
- Cross-surface intent: frontend → own backend → target hook → target notification.
  Exact-client routing has no global-active/broadcast fallback.

- Production app-intent foundation: `app_intent_pipe.rs` registers exact owned
  worker pipes independently of runtime-debug. `app.open` reuses lifecycle URL
  authority; `app.intent.dispatch` forwards allowlisted `app.intent.deliver`
  requests with framework-derived source identity, bounded correlation and no
  mutation replay. Native `AppIntentPipe` schedules bounded requests on the domain
  loop; `document.open` reuses the Sidebar live-client/active-slot/app checks and
  requires the current presentation ID. `sidebar.openApp` and Explorer directory
  opening reuse `host/sidebar_app_backend.py`: pipe launch, pre/post client and
  project-generation fences, shared ledger membership, exact-client activation.
  Project opening uses the guarded service below; remaining app UI integration is tracked separately. No arbitrary method
  dispatch or fabricated socket session. Contract:
  `docs/apps/sidebar_app_intents/PLAN.md`, **Production Pipe Foundation**.

- Terminal intents: `host/terminal_intent_backend.py` serves Explorer and pipe
  `terminal.createSession`, with live-client/presentation/project-generation
  fences. Explicit-CWD drawer creation adds shared membership without global
  selection/rebind; exact-client `ui.terminal.open` carries the shell ID. Sidebar
  Terminal launches consume `new_session` on their own lifecycle lane, matching
  UUID/CWD claims in retained FWS shell metadata before reuse. Successful boot
  publishes concrete `shell_id`; no uncertain automatic retry. Claims are not
  a permanent journal after FWS record removal. See sidebar-app PLAN,
  **Terminal Intent Slice**; client-local destination uses the host choice contract
  below, while other app callers remain pending.

- Ordinary Sidebar app presentations carry `clientInstanceId` and `presentationId`, not only extension views. File Explorer embedded document/terminal intent uses its own backend then the framework pipe; missing embedded identity must not fall back to full-page navigation. External-file routing is shared at the editor-open service: outside-project files become stateful CM6 tabs, inside-project files use the exact-client editor hook. CM6 publishes file query state and skips app-global last-file/draft restoration when embedded. See `docs/apps/sidebar_app_intents/PLAN.md` for guarded project adoption and CM6 settings/navigation contracts.

- File Explorer project opening uses its own backend plus pipe `project.openDirectory` when embedded; standalone `project` query is consumed once by host boot before snapshot/model restoration via authenticated `ui.host.project.directory`. Backend-owned single-use 120s consent tickets fence client/presentation, directory identity and project generation; shared switch revalidates after async cleanup before root mutation. Cancel/failure does not retry or clear drafts. Known projects restore; existing unknown directories are adopted without nested creation. File Explorer item context menus reuse enabled File/Edit actions and clear unrelated batch selection. See sidebar-app PLAN, **Project Intent Slice**, and CODE_TE2.md, **Production Projects Modal**.

- Generic app-shell `api.get/post/delete` call `teFetch`, which validates HTTP/body success and already returns `body.data`. App frontend adapters consume that DTO directly; never unwrap `.data` again. Project-intent regression executes the template's actual `teFetch` to preserve this boundary.

- Shared Code TE2 editor-open service canonicalizes external paths (including symlink escapes) and routes them through backend-owned exact-client CM6 Sidebar creation before project-model/recents effects. Sidebar presentation guards remain validated through launch. CM6 persists five preferences only in `te2:file-editor:preferences:v1`; draft/path/credentials stay separate. Its modal awaits the original guarded action; successful Save/Discard resumes once, Cancel/failed Save cannot navigate. Generic app-shell exits await async guards; `onBeforeUnload` supplies a separate synchronous dirty check. See sidebar-app PLAN, **Combined File Explorer / CM6 Completion Slice**.

## Domain Guards To Read Before Editing

- **Sidebar:** shared ledger owns membership/lifecycle; client stores own order,
  visibility and presentation. Random relay origins are not persistence keys.
  Empty/incomplete activation/reset snapshots do not prune membership. Preserve
  parked projects/hidden views; only explicit user intent reveals hidden views.
  No expiry/polling/new backend preference tier. Read CODE_TE2.md,
  **Sidebar Membership And Host Presentation Ownership**, **UI VSIX Webviews And Editor Contributions**.
- **Search/Git/History:** retained hits, actual index state and selected comparison
  are different authorities. Historical stage/commit/reset are rejected; Restore
  writes current worktree with draft consent and preserves index, never moves HEAD.
  Guarded edits are exact-client/project/revision/SHA/range scoped; uncertain
  accepted writes are not retried. History uses attributed upstream SCM copies;
  immutable historical models never enter WBA or allow Save/discard/mutation.
  Read **Search system**, **Source Control History Component Foundation**,
  **Secondary History Content State Foundation**, and comparison/Restore in CODE_TE2.md.
- **WBA:** logical documents are shared, facades exact-client; releasing one client
  must not release another's document. Visible open completion is separate from
  intelligence acknowledgement. Python diagnostics serve Explorer/Problems only;
  no editor nudges. Generic selector matching, no language-specific routing hacks.
  Read **WBA Logical Documents And Multi-File Extension Handling**,
  **Multi-provider language features**, **Diagnostics owner-keyed markers**.
- **Intelligence:** browser-worker/managed-Code-Server modes are mutually exclusive,
  without silent fallback. Managed runtime is pinned/private/confirmation-gated;
  system/PATH/NVM overrides are not authorities. `intelligence.json` owns install/mode;
  WBA imports pinned RPC IDs, not runtime NID/version probes. Do not restore the
  removed extension watcher bridge. Read **Monaco language backend modes and ownership**,
  **Code-Server Installer**, **RPC Protocol IDs**, **Extension Configuration**, **Compact Completion Projection And Lifecycle**.
- **First model:** backend-owned selected theme/grammar catalog and active grammar
  must satisfy the exact authenticated client's editor-RPC barrier before mounting.
  Socket construction/another warm client is not readiness; no WBA/HTTP fallback.
  Read CODE_TE2.md's theme/TextMate boot and reconnect contracts before changing them.
- **UI/input:** authored Code TE2 controls use app-owned popup/listboxes, not native
  `<select>`; teUI dialogs replace browser prompts. Keep JSON editor fields and
  autocapitalization disabled on separately hosted/new inputs too. Android keeps
  detached guarded-line input; no native EditContext/composition gating/raw-key
  newline suppression. Gesture handles, focused secondary rails and historical
  read-only tools retain their distinct owners. Read **Android / GeckoView IME and
  Browser Text Input**, **Touch selection**, **Shared UI And Input Policy**.
- **Terminal:** standalone Node/node-pty/headless-xterm and drawer Python/Pyte domain
  projection have distinct ownership; drawer PTY/I/O is native on this branch.
  Preserve canonical raw-log offsets/checkpoints and exact shell/session removal.
  No polling, decoded fallback, text-overlap guesses, dead-shell reopening or
  routine retained-screen resize. Empty/non-terminal drawer opens create no PTY.
  Read **Code TE2 Terminal Drawer Transport**, **Standalone Terminal Contracts**.

- Explorer expanded-card header spacing is CSS-owned: zero grid/list margins with 3px top-only list padding and the first child's 4px margin. Retain indentation/sibling spacing; do not compensate in sticky-scope JavaScript. See CODE_TE2.md, Search system.

- Explorer Changes expandable headers toggle only; diff rows/bodyless previews navigate. Actual index state drives Unstage (including partial staging), never comparison appearance; retain HEAD guards and guarded Restore. MRU/expanded outlines belong to complete file groups. See CODE_TE2.md, Search/Git comparison contracts.

- Contents/Changes result scopes use native CSS sticky on original live headers, bounded by file/hunk DOM boxes (`overflow: clip`, not a scrolling ancestor). Contents requires 3 displayed hits; Changes docks hunks under its 34px file row. Keep group outlines open beneath docked headers; source-tree sticky projection is separate. See CODE_TE2.md.

- Explicit sidebar app-intent launch activation requests `revealSidebar`; the initiating host opens the sidebar and closes Explorer only in mobile layout. Restore/reconnect activation must not force layout reveal. Reuse existing open/close helpers, never toggle an already-open sidebar.

- Successful Sidebar document opens into the project editor emit exact-client `ui.sidebar.drawer.close` on the host UI IPC lane with `mobileOnly` feedback. Its explicit host contract/parser maps to the local `sidebar.drawer.close` presentation event; sending the Sidebar-lane method directly on UI IPC is silently rejected. The host closes the sidebar and toasts only at the mobile breakpoint; desktop and external CM6 sidebar opens retain their layout. Feedback follows backend open dispatch, not completed Monaco mounting. Test the real wire parser, not only the DOM event.

- New terminal PTYs explicitly advertise `TERM=xterm-256color`: standalone Node broker sets both node-pty name and child environment; native Code TE2 drawer overrides rendered shell env. Never inherit `tmux-256color` from the framework launcher into an xterm-served PTY. The user verified this inherited mismatch caused broken touch interaction in htop. Existing sessions keep their environment until recreated; a user-launched tmux inside a new shell may set its own TERM normally.

- Source-tree sticky scopes must refresh on mobile Explorer drawer open and its settled transform, with a visibility-observer refresh for nonanimated reveals. Offscreen rendering can leave a root-only projection without any later resize/scroll; manual update restored nested scopes on both live clients without scrolling. Keep the existing geometry and clean up observer/listener ownership; no polling or backend-state repair. See sidebar-app PLAN/TRACKER for validation versus pending OTA acceptance.

- Sidebar dock overflow belongs to the header icon strip, not the popup/menu parent: retain an 80px minimum title area and independent fixed icon cells. Overflowing horizontal touch gestures scroll; vertical-start touch and mouse gestures retain reorder. Scroll claims cancel pending long-press/reorder and suppress accidental activation, without changing membership/preferences. Keep popup siblings unclipped and dispose scroll bindings on projection rerender.

- Explorer and launcher controls stay fixed to the left of the Sidebar app-icon scrolling viewport; only app icons scroll between those controls and the window title. Menus remain outside the overflow strip. Preserve this split when rebuilding dock projections.

- Terminal directory destination is client/configured-framework scoped across projects, stored separately from dock state in existing native containers (browser localStorage only). Editor Settings beneath Cursor style can restore Ask every time. Both Explorer callers ask the initiating Code TE2 host via backend-owned exact-client notification/reply; a bounded single-use pending ticket prevents holding the framework pipe open for user choice. Source/version and native bridge publication must match; no PTY is created by changing this preference. See sidebar-app PLAN, Terminal Intent Slice, and CODE_TE2.md, Per-host presentation.

## Native Lifecycle And Publication

- GeckoView remains primary; Cefrium is isolated. `PersistentNetworkService` owns
  Android relay/routes/UI IPC/console across activity recreation. Cold restore
  requires fresh route authority; route listeners and Inspector targets are separate.
  Do not duplicate service-owned transports in activities or persist routes as authority.
- Cefrium's standalone `android/cefrium` build uses its own JDK 25/SDK 37 setup;
  do not invoke it as a root Android subproject. Keep compile-only Window Extensions
  interface dependency, not the duplicate keep rule. Preserve renderer-specific
  input font safeguards; pinch policy is not universal page-scale suppression.
- Electron IPC/presentation and primary/secondary identities stay validated and
  distinct; existing native UI IPC reconnect owns route readiness. Exit stops only
  Electron's owned framework child, never an external/remote framework.
- Frontend checks: `npm run typecheck`, `node build.mjs` in `app/apps/code_te2`.
  Output is `static/dist/host.js`, not `editor.js`. Synchronize release-facing
  versions for native frontend contracts; build frontend before approved bundling.
  Check ≥2 GB free before Android builds; retain debug/release inspection isolation.
- Verified binary installs must not silently build/fall back to Cargo. Preserve
  checksum/features/ABI/provenance and accepted archives; no release-performance
  claim from isolated import or fixture tests. Consult **Build And Installation
  Contracts**, native-worker README and client-runtime `PLAN.md` before packaging.

- Monaco bootstrap's authored adjacent `monaco.bootstrap.bundle.d.ts` declares loader options and an opaque namespace, narrowed at consumer boundaries; do not infer types by parsing the generated multi-megabyte bundle. Monaco environment configuration uses the pinned `editor.api` Environment type, not a generic string-keyed record.
