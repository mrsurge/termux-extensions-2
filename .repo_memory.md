# TE2 Repository Memory

This file is concise durable orientation. Current source is authoritative;
update or remove any memory entry that source supersedes.

## Workflow

- New repository changes use prompt approval, read-only investigation, final
  plan approval, then execution of only the approved scope.
- Preserve user changes and untracked files. `android/` is read-only unless an
  approved plan explicitly includes it.
- Never restart the shared TE2 framework runtime without explicit approval.
- Use `$TMPDIR` for scratch data when set; otherwise use a named workspace-local
  scratch directory rather than hard-coding `/tmp`.

## Runtime Authority

- The supported framework is the Rust server under `rust-spike/rust/`.
  `rust-spike` is a historical path name, not an indication that the Python
  framework remains primary.
- `te2` and `te2-rust` resolve through `app/cli/run_rust_framework.py`, which
  loads `rust-spike/app/bootstrap.py`. The bootstrap builds/reuses a
  fingerprinted Rust binary, starts the Python runtime bridge, and forwards
  signals to the Rust server.
- The retired Python framework, supervisor, app lifecycle/runtime, generic
  extension backends, and duplicate Python Git provider were removed. Do not
  restore them as fallbacks.
- This is a hard Rust framework cutover. Python outside app code is retained
  only when the packaged Rust launcher, the Axum-proxied console/FastMCP
  sidecar, or a Rust-launched app worker imports it. There is no Python
  compatibility framework, supervisor, or IPC lifecycle service.

## Retained Python Boundary

- `app/te2_runtime_mounts.py`, `app/te2_console_runtime.py`, and `app/te2_mcp/`
  provide the runtime bridge for TE2 console and MCP.
- `app/extensions/apps/registry.py`, `manifest_validation.py`, and `scaffold.py`
  provide manifest catalog/scaffolding support; Rust owns live app lifecycle and
  proxy behavior.
- `app/libs/app_worker.py`, `pipe_protocol.py`, and `pipe_runtime.py` support
  Python app workers connected to Rust framework services.
- `app/libs/jobs.py`, `archiver.py`, and `archiver_service.py` remain because
  current apps use them. Archive access uses `libarchive-c`; do not add the
  conflicting `libarchive` distribution.
- App-specific Python backends live under `app/apps/`.

## Framework And App Assets

- Rust serves the framework shell from `app/templates/` and `app/static/`.
- Built-in apps live under `app/apps/`; user-local apps live under
  `~/.local/share/te2/apps`.
- The root launcher still consumes the app-launcher frontend in
  `app/extensions/apps/`, but legacy generic extensions are intentionally gone.
- App manifests are the app catalog contract. Apps with semantic backend
  readiness opt in through `readiness_support: true` and publish readiness to
  `/api/apps/{app_id}/readiness`.
- Framework-readiness app shells use one app-scoped
  `/api/apps/events?app_id=...` SSE stream. Its initial snapshot carries the
  manifest projection, current readiness, persisted shell state, and debug
  setting; subsequent `app_readiness_changed` facts release cold launches.
  Cold launches keep the universal readiness placeholder visible, while hot
  loads proceed from an initial `ready` snapshot. Do not restore serialized
  catalog/settings/state/readiness GETs or `/ws/apps` as an app-shell boot gate.
- Framework services for filesystem, Git, search, bookmarks, settings, state,
  app lifecycle, proxying, and shell orchestration are Rust/Ferrous-owned.
- The vendored browser font in `app/static/fonts/jetbrains/webfonts/` is the
  complete Nerd Fonts v3.4.0 JetBrains Mono NFM glyph corpus, published as only
  Regular, Italic, Bold, and BoldItalic WOFF2 faces under the existing asset
  filenames. Do not restore the release archive, desktop TTFs, variable fonts,
  no-ligature duplicates, proportional variants, or unused weight files.

## Code TE2 Source And Ownership

- Code TE2 is `app/apps/file_editor_cm6`.
- Host frontend entry: `main.ts`; host source:
  `main_page/frontend/`; generated host bundle: `static/dist/host.js`.
- Editor frontend entry: `monaco_editor/m_editor_app.ts`; editor source and
  editor backend services live under `monaco_editor/`.
- Explorer frontend lives under `src/explorer/`; Explorer backend/RPC code lives
  under `explorer/`.
- Host backend actions live under `host/`; UI and Sidebar IPC live under
  `ui_ipc/`; WBA lives under `workbench_protocol_proxy/`.
- The Explorer header keeps its collapse control visible in both responsive
  layouts, immediately before the project label. Project creation, directory
  opening, and the existing Projects/recent-project modal are grouped under the
  `Project…` dropdown beside the Explorer ellipsis menu.
- Active-file authority is `ProjectSidecar.last_file`, coordinated through
  `open_state_backend.py` and editor open services. Frontend path variables are
  projections.
- Frontends use only their own RPC lanes: editor `/rpc/editor`, Explorer
  `/rpc/explorer`, host `/ui_ipc`, sidebar backends `/sidebar_ipc`, terminal
  `/terminal`, WBA `/wba`, and framework console `/te2_console`. The standalone
  terminal frontend additionally publishes only IME focus/blur hints to
  `/ui_ipc` for the native wrapper.
- Explorer, editor/Python, direct editor/WBA, and UI IPC require strict
  `msgpack-v1` application payloads over their existing Socket.IO namespaces.
  Browser encoding is owned by `src/rpc/codec.ts`; Python encoding, decoding,
  strict auth validation, and default-off stdout metrics are owned by
  `frontend_rpc_codec.py`; WBA runtime encoding is owned by
  `workbench_protocol_proxy/node_workbench_adapter/src/protocol/messagepack-codec.ts`.
  These migrated lanes have no JSON fallback.
- Direct editor/WBA language intelligence remains a frontend-to-WBA hot path.
  MessagePack changes its application payload codec only; it does not route
  hover, completion, symbols, semantic tokens, inlay hints, or other WBA calls
  through Python or the worker event bus.
- Sidebar IPC retains its current codec. The standalone terminal app's separate
  `/ui_ipc` IME hint connection uses strict `msgpack-v1`. Migrating `/ui_ipc`
  must not implicitly change the sibling `/sidebar_ipc` namespace.
- `FILE_EDITOR_CM6_RPC_CODEC_METRICS=1` enables Python Explorer, editor, and UI
  IPC codec metadata on stdout; it is declared as `0` in the app-worker
  shellspec and does not inspect payloads or take timing measurements while
  disabled.
- Cross-surface actions flow frontend -> own backend -> target backend hook ->
  target notification. Do not connect one frontend directly to another lane.
- Code TE2 Git and search jobs use Rust pipe services. The old generic Python
  Git job registration/listener is gone; generic Python jobs remain only for
  current non-Git app work such as archive extraction.
- Code TE2 resolves one code-server installation for launch, version probing,
  builtin extensions, and WBA nid extraction. Resolution prefers
  `TE2_CODE_SERVER_BIN`, then `PATH`, the login shell, NVM installations,
  `$PREFIX/bin`, and `~/.local/bin`. The resolved launcher directory is
  prepended to the code-server process `PATH` so NVM's `#!/usr/bin/env node`
  launcher works even when NVM was not initialized in the app-worker shell.
  `TE2_CODE_SERVER_BIN=/absolute/path/to/code-server te2` is the supported
  entry-point override and is inherited through Rust/Ferrous.
- WBA nid extraction structurally parses the minified `MainContext` and
  `ExtHostContext` proxy objects and accepts JavaScript factory identifiers such
  as both `N` (Code OSS 1.109) and `$` (Code OSS 1.117). When
  `extHost.protocol.ts` ships with code-server, its declaration order is a
  fallback and cross-check. The uploaded code-server 4.117 bundle was verified
  as an exact 160-entry match to its pinned Code OSS commit
  `10c8e557c8b9f9ed0a87f61f1c9a44bde731c409`.
- WBA language-intelligence requests receive the resolved
  `ExtHostLanguageFeatures` nid through their runtime adapters. The numeric
  `94` is retained only as the Code OSS 1.109 fallback in `RPC_DEFAULTS`; no
  hover, completion, symbol, folding, semantic-token, inlay-hint,
  inline-completion, or document-color call site hard-codes it.

- The installed WBA MessagePack codec is one self-contained bundled ESM file
  at `workbench_protocol_proxy/node_workbench_adapter/dist/protocol/messagepack-codec.mjs`.
  The rest of the WBA module graph remains split, and installed runtimes must
  not resolve `@msgpack/msgpack` from the development `node_modules` tree.

- Android `UiIpcClient` is also a strict `msgpack-v1` consumer on
  `/ui_ipc`: its Socket.IO namespace auth declares the codec and
  `UiIpcMessagePackDecoder` decodes binary focus/blur notifications with
  `msgpack-core`. It has no JSON fallback. The separate native
  `/te2_console` connection retains its existing JSON event payloads.

- Code TE2's patched touch-selection source is
  `worktrees/monaco-touch-selection/src/`; `dist/index.umd.cjs` and
  `dist/style.css` are copied into
  `app/apps/file_editor_cm6/static/vendor/monaco-touch-selection/` as generated
  deployment artifacts. Handle drag uses raw CSS-pixel touch coordinates,
  resolves horizontal placement against every rendered Monaco insertion
  boundary, and samples the latest touch on one fixed 50 ms loop. Active drag
  cleanup owns its timer and document listeners, and repeated positions do not
  write duplicate Monaco selections. Touch handle interactions auto-open one
  centered adjustment island containing shrink-left, grow-left, grow-right,
  and shrink-right flush against the primary menu. Both rows retain the
  original 2.4rem control size and overlap by one border pixel inside a shared
  root stack, so seam touches cannot dismiss the menu. The handles remain at
  layer 40 while the menu uses layer 350 above host Explorer, sidebar, menubar,
  and toolbar chrome but below framework dropdowns and modals. Desktop
  right-click opens only the primary row. Teardrop visuals retain their
  existing size while pseudo-elements provide the enlarged touch targets.

- Code TE2's default Monaco font is the locally vendored `JetBrains Mono Nerd`
  family under `app/static/fonts/jetbrains/webfonts/`, with regular, italic,
  bold, and bold-italic faces declared by the app template. Monaco enables
  `fontLigatures`; a custom font preference can replace the default family.

- Android Gboard recomposition handling is authored in
  `worktrees/vscode-te2-diff` at the Monaco
  `TextAreaEditContext`/`TextAreaInput` boundary. Android uses a physically
  detached textarea containing `\u21dd` + the complete model line + two
  trailing newlines. Native `input` events coalesce to one latest-value read
  per animation frame; one cumulative UTF-16 range edit is applied before a
  generation-guarded canonical reseed. Android composition start/update/end
  events do not gate input or create Monaco's visible composition textarea.
  Selection-only native movement does not move Monaco, and synthetic taps
  flush accepted browser-owned text before pointer relocation. The former
  35 ms rapid classifier, 140 ms settle timer, pending cursor, transparent
  foreground textarea, and empty-state composition teardown are removed.
  Publication runs `editor-distro`, overlays scoped ESM/CSS into
  `app/static/vendor/monaco-editor-core/esm`, regenerates the Monaco
  bootstrap, and rebuilds Code TE2 `static/dist/host.js`. This detached
  transaction is synchronized as TE2 `0.2.320`; no Android native source is
  involved, and mobile browser/wrapper validation remains required.

- Monaco native `EditContext` is intentionally disabled when
  `browser.isAndroid` is true, even if Chromium exposes the API. Android
  Chromium and Gecko therefore share the patched `TextAreaEditContext` Gboard
  transaction path; desktop Chromium retains native `EditContext`.

- The inline Monaco editor host remains at `z-index: auto`. Only its
  `.find-widget` is raised to `z-index: 300`, above drawers and resize handles
  but below framework dropdowns and modals; editor-container overflow clipping
  remains intentional.

- Code TE2's Python-owned Socket.IO namespaces (`/rpc/editor`, `/rpc/explorer`, `/ui_ipc`, `/sidebar_ipc`, and `/terminal`) share the canonical public path `/api/app/file_editor_cm6/socket.io`, allowing one browser-realm Engine.IO Manager to multiplex them. WBA remains a separate direct hot path at `/api/app/file_editor_cm6/services/wba/socket.io`; framework console remains separate, and manifest aliases are compatibility-only.
- Code TE2 request/response RPC calls use ordinary Socket.IO `emit` only while
  connected so transport backpressure cannot silently discard a request that
  is waiting for an acknowledgement. Fire-and-forget notifications remain
  `volatile.emit`. After the first connection, disconnected calls fail,
  in-flight requests reject, and each namespace clears its client
  `sendBuffer`, so reconnect never replays stale RPC work; explicit connect
  handlers rebuild authoritative state. Python uses a local `AsyncManager`
  with no disconnected-session recovery, and WBA explicitly leaves
  `connectionStateRecovery` disabled.
- A visible editor file-open transaction ends after Monaco has applied and
  verified the target model and navigation. It does not await WBA model-open
  acknowledgement or agent-edit hydration. WBA model opens use a separate
  single-flight scheduler whose pending slot is latest-wins, preventing both
  frontend open blocking and concurrent WBA model churn during rapid opens.
- TextMate grammar-catalog loading and WASM/factory initialization each share
  one in-flight promise. Per-language tokenizer installation remains
  independently deduplicated.

- The touch-selection UMD exposes `touchSelectionDebug` on `window['monaco-touch-selection']` for exact-worker TE2 console eval. It is disabled by default and uses a bounded JSON-safe ring while enabled. `start()` enables capture, `snapshot()` and `latestDrag()` retrieve records, `stop()` disables capture without discarding records, and `clear()` removes them. Captures include raw and adjusted touch coordinates, DOM hit stacks, rendered boundary candidates, resolver fallbacks, selection writes/events, scroll changes, and cleanup.

- A new Monaco touch-handle drag force-hides any selector menu left open by the preceding tap or drag before enabling `_menuGuard`. The document-root menu must not remain hit-testable over the adjusted caret coordinate, because it causes `getTargetAtClientPoint()` to return no editor position near the previous handle origin.

- During an active Monaco touch-handle drag, `.monaco-editor-touch-selections.dragging` disables pointer hit testing for the handle layer while document listeners continue tracking movement. Authoritative drag cleanup removes the class. Opacity alone is insufficient because the enlarged `::before` touch targets otherwise remain hit-testable at the original handle position and create a dead resolver zone.

- The canonical Socket.IO path topology and touch-selection
  diagnostics/hit-testing corrections were synchronized as TE2 `0.2.323`.
  Reliable request delivery, non-blocking rapid file opens, latest-wins WBA
  hydration, and deduplicated TextMate initialization are synchronized as TE2
  `0.2.324`.

- Android Gecko shows a persistent translucent bottom-right keyboard recovery
  control mounted under the stable host-owned `#editor-frame`, outside Monaco's
  replaceable DOM. It has no native IME visibility bridge, lifecycle handshake,
  keyboard-state predicate, or editor-focus predicate; its trusted click only
  blurs and refocuses the writable Monaco textarea. Other clients do not create
  the control. This stable overlay and the APK-owned canonical asset seed are
  synchronized as TE2 `0.2.326`.

- Code TE2 extension observability is WBA-owned. The adapter projects
  activation/runtime errors, extension-host warnings, extension-contributed
  status entries, and output/logger channel descriptors from native MainThread
  RPC families into a bounded registry. Browser clients use
  `extensions.activity.snapshot` and `extensions.logs.select` over the existing
  `/wba` transport. Selected file-backed logs use bounded initial tails plus
  `fs.watch` delta reads; direct logger RPC content is separately bounded. The
  host renders the projection in the bottom status row and Extensions drawer
  without another socket or Python routing. Extension-contributed status
  commands remain display-only until a command bridge is implemented.

- The Extensions drawer uses the same in-DOM button plus `role="listbox"`
  `.fe-dropdown`/`.fe-dd-item` controls as the rest of Code TE2. Do not replace
  its extension or channel filters with native `<select>`, `<dialog>`, or OS UI.

- WBA extension activation derives declared and Code OSS implicit activation events from each executable extension manifest's `contributes` map. A session-scoped awaited broker deduplicates activation by event or arbitrary extension ID, clears on extension-host reset, and leaves failed attempts retryable.
- WBA resolves missing or `plaintext` document language IDs from extension-contributed filenames, extensions, filename patterns, and first-line expressions. File-open starts non-blocking language activation, while language-provider RPCs await both `onLanguage:<id>` and generic `onLanguage`; this path must remain extension-agnostic with no extension-ID or suffix special cases.

- Code TE2 recent-file authority is projected with each sidecar-backed open-state fact. `SidecarOpenStatePayload.recents` is the same bounded 12-entry MRU snapshot produced from the already-loaded `ProjectSidecar`; host boot/state snapshots reuse that projection, and the Recents menu consumes `ui.openState.changed` regardless of whether an open originated from Explorer or the host menubar. The obsolete `ui.host.state.fileActivity.record` reread contract is removed; `ui.host.state.fileScroll.update` remains independent.
- `editor.openComplete.publish` is a required control-plane acknowledgement and uses the editor RPC transport's request/response-backed `publishReliable` path. Ordinary fire-and-forget editor notifications remain volatile, WBA/agent hydration remains outside the visible-open critical path, and disconnected requests are still rejected without replay.

- The Cefrium Android client, WBA extension observability and activation
  routing, sidecar-backed recent-file projection, and reliable editor-open
  completion acknowledgement are synchronized as TE2 `0.2.327`.

- Code TE2 Code Inspector is one backend-retained bottom-drawer projection for References, Implementations, and Call Hierarchy. Explicit editor context-menu actions call WBA directly; WBA performs Code OSS document-selector scoring/order, semantic provider dispatch, reference/implementation merge-sort-deduplication, and lazy call-hierarchy session management. The editor publishes normalized whole projections reliably through `/rpc/editor`; Python retains one revision-guarded projection, emits `CodeInspectorChanged`, projects it through `/ui_ipc`, and rehydrates host reloads through the boot snapshot. Lazy hierarchy expansion and release return through backend-mediated editor commands, so frontends do not call each other. Browser reload does not release the WBA session; project switch, adapter reset, replacement, or worker teardown invalidates it. There is no grep fallback, new socket, or HTTP endpoint.

- Code Inspector's cancellable ExtHost language-feature requests omit the `CancellationToken` argument from their encoded args; request type `2` makes Code OSS append the real token. Do not add `undefined` token placeholders, which serialize as `null` and shadow the injected token. The canonical Code TE2 `build.mjs` WBA entry list must include `code-navigation.ts` so normal frontend builds regenerate its deployment module.

- Code Inspector reference and implementation locations are enriched in WBA with source previews capped at 240 characters. Preview reads are deduplicated per file with bounded concurrency; the editor replaces the active file's preview from Monaco's live model so unsaved text remains authoritative.
- Code Inspector semantic hits use the existing Monaco `findMatch` decoration shape through a separate decoration collection from contents search. Hits are filtered to the active path, reapplied after file/open-state changes, and cleared on replacement, project switching, or runtime disposal.

## Standalone Terminal

- `app/apps/terminal` supports only
  `shellspec/node_terminal_stream.yaml`; the Python and native terminal
  shellspecs were removed and dead shells are not reopened.
- The persistent Node worker owns `node-pty`, `xterm-headless`, 5,000 rows of
  parsed scrollback, sequence assignment, and `SerializeAddon` checkpoints.
  Reconnect attaches serialize at sequence N, then release only output newer
  than N; historical FWS log tails are not a terminal-state source.
- Browser traffic at `/ws/app/terminal/terminal?codec=msgpack-v1` is strict
  binary MessagePack with one object per WebSocket frame. Framework-Shell pipe
  traffic is `uint32` big-endian length-prefixed MessagePack. Python uses
  `msgspec.msgpack`; Node/browser use `@msgpack/msgpack`; there is no JSON,
  base64, or alternate shell-codec fallback.
- `xterm-headless@5.3.0` and `xterm-addon-serialize@0.11.0` intentionally match
  the vendored browser `xterm@5.3.0`. The worker removes Node 21+'s browser-like
  `navigator` global before loading these legacy headless packages.
- The Terminal Python backend atomically bootstraps its locked production Node
  dependencies under `$XDG_DATA_HOME/te2/node_runtime/terminal`, keyed by the
  package lock, platform, architecture, and Node ABI. It passes the resolved
  Node binary and runtime root to Framework-Shells; installed packages never
  depend on the source checkout's pruned `node_modules` tree.

- Both browser terminal surfaces load one shared `xterm@5.3.0` asset from
  `app/static/vendor/xterm/`. Its readable source fork is
  `worktrees/xterm-te2` on branch `te2-android-ime`, based on upstream tag
  `5.3.0` (`2e02c37e528c1abc200ce401f49d0d7eae330e63`);
  `TE2_PATCH_GUIDE.md` owns validation, publication, and rebase instructions.
  Android uses a detached cumulative textarea transaction, suppresses xterm's
  composition overlay, coalesces native input once per animation frame, and
  emits only current-transaction suffix corrections through xterm's normal
  `onData` event. Desktop and screen-reader composition retain upstream
  behavior.

- The published xterm fork origin is
  `https://github.com/mrsurge/xterm-te2.git`; the official
  `https://github.com/xtermjs/xterm.js.git` remote remains `upstream`.

## Build And Publication

- Python package metadata and CLI entrypoints live in `pyproject.toml`; runtime
  dependencies live in `requirements.txt`.
- Framework releases keep the version in `pyproject.toml`, the Rust server
  crate, `app/apps/file_editor_cm6/static/version.txt`, the App Launcher
  manifest, every active built-in app manifest, and versioned frontend asset
  URLs synchronized. The shippable Electron desktop package and its
  `package.json` application version participate in the same release
  version. Dependency and protocol-schema versions are independent.
- Code TE2 frontend changes require `npm run typecheck` and `node build.mjs` in
  `app/apps/file_editor_cm6` before handoff.
- Code TE2 has one browser build output: `static/dist/host.js`. The inline
  Monaco runtime and editor application are statically bundled into that host;
  do not restore a standalone Monaco bootstrap request or `static/dist/editor.js`.
- Rust validation should preserve its target cache and use proportional Cargo
  format/check/tests.
- Android bundled assets are a separate publication path. Do not publish or
  modify Android assets unless that scope is explicitly approved.
- GeckoView Home loads the Android-owned web shell from `app/android_shell/`
  through the activity's loopback
  `LocalAssetServer`; it does not load the framework splash page. The local
  launcher has a compile-time frontend extension registry and projects the
  framework `/api/apps/catalog` through `/android-api`. It always contributes
  local Settings, which is the only app shown when the framework is offline.
- `LocalAssetServer` binds and publishes the same explicit IPv4 loopback
  address (`127.0.0.1`) and fails startup when no port is assigned. Do not use
  the platform-selected loopback address while emitting an IPv4-only URL, and
  do not perform a client socket probe synchronously from activity `onCreate`.
- Android wrapper diagnostics use this process's bounded warning/error logcat
  as the source of truth. A per-activity marker creates the session boundary;
  native Tools and `GET /android-api/debug` project it on demand, while only
  startup-blocking failures produce toasts.
- Gecko's asset WebExtension redirects declared static requests to the APK
  loopback server on a different port. Monaco module workers therefore use a
  same-origin `blob:` bootstrap on real Gecko runtimes and import the declared
  worker URL from there; direct top-level module-worker redirects fail before
  Monaco can compute inline diffs.
- Android Settings are local `SharedPreferences` state owned by
  `AndroidAppSettingsStore`. Framework host/port, the persistent-network
  toggle, the default-on native IME context-switching toggle, and the
  default-off native developer-tools toggle do not read or write framework `/api/settings` or
  `/api/android/config`. Boolean toggles persist immediately when changed;
  the Settings Save button updates only framework host/port. Disabling IME
  context switching ignores only UI IPC editor/IME focus facts and clears the
  native input filter; `/ui_ipc` and the lazy `/te2_console` lane remain
  connected. The local Settings page embeds the configured framework `/fws`
  view only after a successful gateway probe.
- `UiIpcClient` connects to the complete locally configured framework origin;
  it must not reconstruct that origin as loopback plus a port. A managed
  loopback TCP relay is a separate, deferred subsystem and is not present in
  the local-shell slice.
- Android GeckoView OTA interception is origin-independent and limited
  to exact files or complete static trees declared by the OTA inventory. Code
  TE2 shell/template/host assets, editor styles, Monaco workers, TextMate,
  themes, and helper assets resolve locally; dynamic APIs and socket traffic do
  not. OTA version and bundle requests use the full configured framework base
  URL.
- Gecko static interception is fail-closed for declared subresources. A blank
  Gecko session opens first so the built-in WebExtension can establish
  `nativeMessaging`; restore/navigation remains gated on its
  `LocalAssetServer` acknowledgement. Top-level framework documents are never
  redirected because that would change their origin and break relative API and
  socket URLs. Declared Code TE2 static paths are redirected locally or
  canceled and never fall through to the framework network origin. Because the
  process-wide `GeckoRuntime` survives activity recreation, activity teardown
  unregisters and disconnects the asset extension native port before stopping
  its activity-owned `LocalAssetServer`; the extension reconnect loop then
  binds the relaunched activity to its new local-server port.
- Android asset publication is monotonic. APK seeding never replaces newer
  installed assets, OTA version checks ignore older server versions, staged
  bundles are version-checked before swap, and a failed swap restores the last
  valid local tree. The APK seed must be regenerated after the final Code TE2
  browser build.
- Android pages carrying the persisted `gv_native` mode do not use the PWA
  Service Worker. The index and app shell unregister existing workers, delete
  `te2-v*` caches, and perform one guarded reload before app boot when the
  current page is still controlled. Normal browser PWA clients retain the
  worker, which intercepts only explicit cacheable assets and navigations;
  non-cacheable scripts and modules use the browser network path directly.
- Android native UI IPC and `source=android_console` use websocket-only
  Socket.IO transports with Engine.IO upgrade disabled. The browser
  `console_bridge.js` is already bundled into `host.js`; the native console
  client is Kotlin-owned and remains lazy to the native Tools overlay. Browser
  console startup is fire-and-forget after core UI IPC connects and must not
  gate UI IPC or editor boot.
- Android package releases track the Code TE2 payload release in
  `versionName` (for example `1.0.7-r0.2.307`, plus the flavor suffix) and use
  a monotonic payload-derived `versionCode` (for example `20307`).

- The canonical Android launcher/Settings frontend source is
  `app/android_shell/`, which is packaged with TE2. The server OTA builder and
  `scripts/bundle_gecko_assets.sh` both consume
  `app/android_editor_assets_bundle.json`; the script stages and atomically
  replaces `android/app/src/main/assets/editor_static/` for APK publication.
  Do not restore a second handwritten asset list. OTA installation replaces the
  complete local asset tree, and `EditorAssetManager` rejects staged bundles
  missing any required launcher file before renaming the installed tree.

- Rust `/api/editor_assets_bundle` builds each OTA ZIP from the current manifest
  sources and returns it with `Cache-Control: no-store`. Do not restore
  version-only ZIP caching: force-updating the same version must not install
  stale asset bytes under a current `version.txt`.

- Code TE2's CM6 JSON fields dynamically import
  `/static/vendor/codemirror.1/codemirror.bundle.js`. Gecko executes the
  locally redirected `host.js` from `LocalAssetServer`, so that root-relative
  module specifier resolves against the local asset-server origin. The complete
  `codemirror.1` tree must remain in both OTA and APK asset production and the
  bundle file is a required staged-OTA asset; otherwise strict Gecko loading
  fails with a local 404 and the fields fall back to textareas.

- CM6 JSON fields can mount inside initially closed disclosure controls, such as
  Run Profiles `Raw JSON`. Gecko may report transiently invalid CodeMirror
  measurements on the first frame after opening. `createJsonTextmateField`
  therefore retries `requestMeasure()` over a bounded six-frame settling
  window before restoring its textarea fallback; do not restore the former
  one-shot measurement rejection.

- The shared Android `MainActivity` is locked to `sensorPortrait` in the base
  manifest, so GeckoView can use either portrait direction but cannot enter the
  unsupported landscape geometry.

- GeckoView writes an app-private runtime config before creating its
  process-wide `GeckoRuntime`; `dom.securecontext.allowlist` contains the
  persisted Android `frameworkHost` without restricting it to loopback or a

  native Android Cut/Copy/Paste/Select actions remain available while
  clipboard-read permission is automatically allowed for the trusted wrapper

  leaving APZ enabled. Forced user scaling is disabled so the native app

  without disabling APZ. The shell also declares
  `interactive-widget=resizes-content`, which keeps the layout viewport,

  open. Because the runtime is process-wide, a changed host or runtime setting
  takes effect after the Android app process restarts.

- Android builds pin GeckoView `144.0.20251027123126` for 16 KB page compatibility. The verified build tuple is Gradle `8.11.1`, AGP `8.9.1`, Kotlin/Compose compiler plugin `2.2.10`, `compileSdk` 36, and `targetSdk` 34. Debug and staging APK audits must confirm every packaged arm64 Gecko library has `PT_LOAD` alignment `0x4000` and the APK passes build-tools 36 `zipalign -c -P 16 -v 4`.

R8 also suppresses the unavailable JDK-only `sun.nio.ch.DirectBuffer` optimization reference; do not remove these rules while native `/ui_ipc` uses MessagePack.

- The persisted Android Settings label `Android IME composition workaround` maps to `imeContextSwitchingEnabled`. It controls only the Kotlin `EditorInputFilter` and UI-IPC focus/blur activation; Monaco's browser-side IME behavior is independent.
- Android native Tools keeps its lazy TE2 Console and persistent native Developer Tools inspector as separate tabs. `devToolsInspectorEnabled` is local `SharedPreferences` state, defaults off, and reloads an active app after document-start instrumentation is enabled or disabled. The inspected page receives only headless Chobitsu 1.8.6 target instrumentation; all visible Chii 1.15.5 DevTools UI runs in a separate persistent `GeckoSession` that is hidden, not destroyed, when Tools closes. Gecko brokers raw CDP directly through two GeckoView WebExtension native-messaging ports. `DevToolsProtocolBroker` keeps generation-scoped bounded queues. This path has no framework HTTP, Socket.IO, or WebSocket transport. Gecko's built-in extension revision must change whenever its packaged behavior changes.

- GeckoView in Android `:app` remains the primary Android renderer. The removed
  system WebView implementation is not a fallback. An isolated `:cefrium`

## Desktop Client

- `desktop_client/electron_spike/` is the active Linux desktop client. The
  GTK 4/WebKitGTK 6 implementation in `desktop_client/ui.py` is a behavioral
  reference only. Both consume the desktop launcher and Settings source in
  `desktop_client/android_shell/`.
- Electron is pinned to 43.1.1 and uses Chromium's native Ozone `auto` path, so
  a Wayland session is not forced through X11. A frameless trusted
  `te2-desktop://shell/` root owns the persistent header, launcher/Settings,
  asset version/toasts, zoom, app-scoped Quit, and window controls. Framework
  documents run in a separate `WebContentsView`; Node integration is disabled
  and context isolation is enabled in both renderers.
- The Linux development and packaged launch paths intentionally pass
  `--no-sandbox`. Ubuntu AppArmor blocks the unprivileged namespace sandbox for
  a user-owned Electron tree, while the setuid helper requires a root-owned
  installation. `package.mjs` emits `TE2Desktop` as a launcher for the bundled
  `TE2Desktop-bin`, so no manual flag or root permission step is required.
- Desktop shared assets reuse `/api/editor_version` and
  `/api/editor_assets_bundle`. They install under
  `$XDG_DATA_HOME/te2/desktop_assets` with monotonic version checks, staged
  full-tree validation, backup, atomic rename, and rollback. The Android
  bundle's `android-shell/` tree is intentionally omitted because desktop owns
  a different launcher and Settings surface.
- Successful desktop asset installs refresh relay availability, clear the HTTP
  and generated V8 code caches for `persist:te2-framework`, and reload an
  active app view with cache bypass. When Settings has no app view open, the
  cleared partition makes the next launch hit the local interceptor. Keep
  normal local responses immutable; do not require a process restart to
  activate forced same-version assets. Restart only appeared to fix the old
  bug because the dynamic relay port changed the browser origin.
- Electron binds one dynamically allocated `127.0.0.1` HTTP origin for every
  configured HTTP or HTTPS framework target. Its in-process relay proxies
  ordinary HTTP, streaming SSE, Socket.IO, and raw WebSocket upgrades. It
  serves only inventory-approved installed assets itself from the same browser
  origin, preserving the origin required by Monaco module workers. Native
  lifecycle/catalog requests and asset updates remain direct to the configured
  origin.
- Changing the framework target retargets Electron's existing localhost
  listener, closes active connections, and leaves its browser origin and
  desktop process stable. Header zoom controls persist a 50%-200% level in
  `$XDG_CONFIG_HOME/te2/desktop-shell.json`. App URLs carry `gv_native=1` so
  the PWA Service Worker cannot mask the desktop asset layer.
- Trusted Electron shell IPC resolves structured native-request results.
  Framework connection refusal, timeout, reset, and abort failures use concise
  recoverable errors and a five-second control-plane timeout; they must not
  escape `ipcMain.handle` with Electron stack diagnostics. Launcher refreshes
  are single-flight and render local Settings before network discovery.
- An open framework app is monitored by one sequential status probe. Offline
  state leaves the app view intact and exposes a native-header route back to
  the local launcher; recovery clears the control without restarting Electron.
- Electron's loopback relay owns paired WebSocket socket teardown. Error, FIN,
  end, or close on either peer unpipes and destroys both sides; guarded
  handshake writes cannot target ended sockets. HTTP/SSE browser disconnects
  cancel their upstream request/response streams. Do not suppress these failures
  through a process-global uncaught-exception handler.
- Desktop native Quit is app-scoped: it validates the current framework
  `/app/<app_id>` URL, posts only that app's quit endpoint, and returns to the
  desktop launcher without terminating the Electron wrapper. The header shows the
  installed desktop asset version, and successful automatic asset installs use
  an in-window native toast.
- Desktop implementations consume one static contract from
  `desktop_client/desktop_asset_inventory.json`. Electron's Node asset manager
  uses the same monotonic staged install, full validation, backup, atomic swap,
  rollback, and loopback-only immutable serving semantics as the earlier
  Python and Bun managers.
- The shared desktop launcher reaches Rust catalog/open/quit endpoints through
  its parent native bridge. These remain low-frequency HTTP JSON APIs, not
  Socket.IO MessagePack lanes. The native Electron context menu contains only
  Copy and Paste and invokes those commands directly on the focused renderer;
  it does not depend on GTK/GDK or the page Clipboard API.
- A live packaged Electron validation loaded the local launcher and Code TE2
  app through the relay on Wayland. Both renderer documents reached complete
  state with no runtime diagnostics, the shell reported installed assets from
  the synchronized release, and the packaged launcher exited cleanly.
- Electron Code TE2 app views expose a frozen `window.te2Electron` preload
  bridge. Its identity makes console workers register as
  `electron:main_page:<per-window-suffix>`; browser and Android retain generic
  `main_page` labels. The exact-view/origin-validated allowlist provides only
  native inspection, cache-bypassing reload, launcher home, and forced asset
  update. Forced update returns after install/cache invalidation so console
  clients can inspect its result and invoke reload separately; the Settings
  path performs activation automatically.
- The desktop relay contract is documented in
  `docs/apps/native-js-modal-plan-tracker/DESKTOP_SHELL_IMPLEMENTATION.md`. Its
  in-process server binds one stable dynamic `127.0.0.1` origin, serves only
  inventory-approved local assets, streams other HTTP/SSE requests, tunnels
  raw WebSocket upgrades, and swaps upstream targets by destroying existing
  connections without restarting the desktop process or changing browser
  origin.

## Shared Modal Architecture

- The approved modal refactor is tracked under
  `docs/apps/native-js-modal-plan-tracker/` and covers all active built-in apps
  plus shared framework surfaces. Pass 1 establishes one asynchronous
  `teUI.dialog` contract, removes direct browser `alert`/`confirm`/`prompt`
  calls, and registers existing custom modal lifecycles. Pass 2 adds the
  Electron child-window presenter and makes stateful modal families portable.
- Browser and Android presenters remain inline. Electron uses two child paths:
  a validated preload/IPC host for portable request contracts and one strictly
  named, same-origin `about:blank` child for registered stateful surfaces. The
  blank child stays in the opener's renderer process; DOM nodes and callbacks
  never cross IPC or renderer-process boundaries. App code does not import
  Electron APIs or preserve synchronous blocking-dialog semantics.
- The Electron preload/IPC boundary, reusable child host, sizing, teardown,
  fallback behavior, simple portable-dialog routing, and same-renderer stateful
  portal are implemented. The portal adopts each live modal root into one
  Electron child, keeps nested roots and primitive dialogs in that window, and
  restores the exact node to its placeholder on close, navigation, native
  child close, controller destruction, or teardown. The first generic-field
  conversion was rolled back because it removed required behavior; do not
  reintroduce that flattening.
- Electron portable dialogs reuse one modal child only while their request
  stack is active. When the stack empties, main destroys the child and creates
  a fresh one for the next top-level request; do not restore hide/re-show of an
  idle modal `BrowserWindow`, which is unsupported by many Linux window
  managers. Stateful and portable nested requests still share their current
  active child.
- Current source has no active `<dialog>`/`showModal()` seam to intercept. The
  corrected Pass 1 baseline was 52 blocking browser-dialog calls across six
  built-in apps, the shared file picker, and the shared app shell; active
  source now uses only the asynchronous `teUI.dialog` API. Existing menus,
  listboxes, toasts, drawers, and non-blocking search overlays are not modals.
- `app/static/js/te_dialog.mjs` owns the versioned portable request/result
  contract, inline presenter, nested stack, focus trap/restoration, presenter
  registration, and declared-surface lifecycle registry. Active legacy inline
  modals carry stable `data-te-dialog-surface` IDs.
- `app/static/js/te_modal_surface_portal.mjs` owns Electron stateful adoption,
  style mirroring, stack title/inert state, exact restoration, and dynamic-root
  cleanup. Electron main allows only the named blank child and denies its
  navigation and further popups. The portal is inactive without the read-only
  preload marker, so browser and Android behavior does not change. Style
  mirroring covers the complete source document because app-template styles
  can live outside `<head>`. Recognized rich modal cards fill the desktop child
  client area with no extra portal gutter; their existing body remains the
  bounded scroll container.
- Code TE2 Run Profiles and Settings must retain their CM6 JSON fields. Settings
  also retains the existing multi-module extension, theme, configuration, and
  live DOM-projection behavior. Do not replace these surfaces with generic
  textarea/form contracts. Dynamic surface UI must derive its DOM realm from
  `ownerDocument`; CM6 fields receive `EditorView.setRoot()` and token styles
  after each document adoption/restoration.
- Code TE2 has a dependency-free TSX/JSX-to-DOM layer under
  `main_page/frontend/ui/modal-kit/`. Its first consumer is the existing
  declarative modal shell. Use it incrementally for reusable components without
  replacing complete working controllers.
- The Android/OTA asset manifest already publishes the complete `app/static/js`
  tree. The PWA service worker explicitly precaches `te_ui.js`, `te_dialog.mjs`,
  and `te_modal_surface_portal.mjs`; keep that dependency chain synchronized for
  first-run offline use.
- A live Wayland development smoke through a clean desktop asset root validated
  Settings, nested Extensions, the 33-field BasedPyright configuration UI,
  live CM6 JSON editors, Run Profiles, full stack restoration, and a shared file
  picker containing 41 filesystem entries.
- The completed modal and Electron child-window work is synchronized as TE2
  `0.2.322`. This release did not change Android source, Android package
  metadata, or Android bundled assets.
- Pass 1 received live Android validation on 2026-07-21. The later framework
  release bump did not publish Android assets or change Android package
  metadata.
- The old Code TE2 Android Build Config and crash/draft-recovery template blocks
  had no source owner anywhere in the repository and were removed with the dead
  Android-config CSS. Desktop-child failure fallback belongs to the shared
  inline presenter, not orphaned template markup.
