# TE2 Repository Memory (Candidate)

This is durable operational orientation, not a second technical manual; source is authoritative, so remove or revise entries it supersedes.

## Workflow

- For new repository changes: get prompt approval, investigate read-only, obtain
  approval for the final plan, then execute only that scope.
- Preserve user changes and untracked files. `android/` is read-only unless an
  approved plan explicitly includes it.
- Never restart the shared TE2 framework runtime without explicit approval.
- Use `$TMPDIR` when it is set; otherwise use a named workspace-local scratch
  directory rather than hard-coding `/tmp`.
- `rg` honors the root `.rgignore`. Generated bundles, vendor trees, Android
  assets, worktrees, and archival paths are intentionally ignored. Search an
  ignored target directly or use `rg --no-ignore` only for a purposeful audit.

- The current Ferrous cross-manager termination contract is defective:
  `fws down` and `fws terminate` can terminate the shared framework rather than
  only the selected app worker. Until that contract is repaired, use the
  framework HTTP/Socket lifecycle endpoints for worker refreshes.

## Runtime Authority

- The supported framework is Rust under `framework/rust/`. `te2` and `te2-rust`
  invoke `app/cli/run_rust_framework.py`, which loads the bootstrap, builds or
  reuses the fingerprinted Rust binary, starts the Python runtime bridge, and
  forwards signals. `te2 console` dispatches separately to `console_cli.py`.
- The retired Python framework, supervisor, lifecycle runtime, generic extension
  backends, duplicate Git provider, and Python compatibility fallback are gone.
  Do not restore any of them.
- Rust owns framework filesystem, Git, search, bookmarks, settings, state, app
  lifecycle, proxying, shell orchestration, and the loaded-app/running-app index.
  Ordinary request, WebSocket, proxy, and Socket.IO handling never rediscovers
  FWS metadata or scans `/proc`; only explicit reload/reconciliation may do so.
- The Rust server uses a multi-threaded Tokio runtime. Each app-worker bridge
  has a bounded 256-frame nonblocking queue and dedicated blocking writer:
  dispatch encodes/enqueues only, preserves accepted-frame order, and reports
  saturation, closure, or writer failure without blocking a Tokio worker.

## Retained Python Boundary

- Python is transitional support for the bootstrap/CLI, console/MCP sidecar,
  manifest/scaffolding helpers, app workers, pipe support, and current app
  backends. It is not framework authority.
- `app.libs.jobs` is a core-only persisted job manager/handler registry. Its
  unmounted FastAPI/SSE router and global `/api/jobs` surface were removed.
  TE2 does not directly declare `sse-starlette`; MCP may still pull it in.

## Framework Assets, State, And Migration

- Rust serves framework shell assets from `app/templates/` and `app/static/`.
  Built-ins live in `app/apps/`; user-local app source lives in
  `~/.local/share/te2/apps`.
- App manifests are the catalog contract. Semantic backend readiness opts in
  with `readiness_support: true` and publishes at
  `/api/apps/{app_id}/readiness`.
- Framework-readiness shells use one app-scoped
  `/api/apps/events?app_id=...` SSE stream. Do not restore serialized boot GETs
  or `/ws/apps` as an application-shell gate.
- Framework settings, generic state, and bookmarks have canonical config/data
  roots. TE2-owned per-app durable state is under
  `$TE2_DATA_HOME/app_state/<app_id>`; `$TE2_DATA_HOME/apps/<app_id>` remains
  user-app source, never an app-state partition.
- The JetBrains Mono webfont payload contains only the published WOFF2 Regular,
  Italic, Bold, and BoldItalic faces. Do not restore release archives, TTFs,
  variable/no-ligature/proportional variants, or unused weights.
- Legacy-root recovery is only the standalone dry-run-first
  `te2 migrate-legacy-roots` command. `--apply` requires a stopped framework,
  locks, validates an allowlist, stages atomic replacements, and records a
  versioned one-time receipt. Startup never invokes it.

## Framework Network Exposure

- The Rust framework is loopback-only by default. Bootstrap resolves
  `--broadcast` once into exact bind hosts and immutable Rust exposure policy;
  invalid selectors fail before binding. `te2 --list-interfaces` emits Linux /
  Termux structured JSON using `getifaddrs`.
- Exact IP/CIDR selectors filter peer addresses; interface selectors filter the
  accepted socket's local destination. Loopback is always allowed. One outer
  Axum middleware protects HTTP, SSE, raw WebSockets, Socket.IO, app proxy,
  console, and MCP routes.
- Public bind addresses are distinct from the loopback `TE_FRAMEWORK_URL` given
  to app workers, Framework-Shells, console, and MCP. IPv4 and IPv6 wildcard
  listeners use separate sockets.

## Code TE2 Identity And Source Ownership

- Code TE2 source is `app/apps/code_te2`; its canonical public app id is
  `code_te2`. `main.ts` is the host frontend entry and `static/dist/host.js` is
  generated output. The editor entry is `monaco_editor/m_editor_app.ts`.
- The manifest's `file_editor_cm6` alias is only a bounded request and persisted
  state migration contract. It must never produce another catalog entry, worker,
  Framework-Shell identity, readiness record, or state authority. Generate new
  URLs and identities as `code_te2`.
- Host frontend: `main_page/frontend/`; Explorer frontend/backend: `src/explorer/`
  and `explorer/`; host actions: `host/`; UI and Sidebar IPC: `ui_ipc/`; WBA:
  `workbench_protocol_proxy/`.
- `CODE_TE2.md` is the deep technical reference. Use its source map and the
  named section cited below rather than expanding this file with implementation
  algorithms, protocol transcripts, generated-file detail, or historical plans.

## Code TE2 Client, Surface, And Transport Contracts

- Project membership is the bounded `ProjectSidecar` recent/logical document
  set. Each stable `clientInstanceId` owns one reconnectable foreground through
  `open_state_backend.py` and `ProjectSidecar.client_foregrounds`; legacy
  `last_file` is a one-time seed. `windowId` is presentation/observability
  metadata, never editor authority.
- Client foreground entries retain their authenticated primary/secondary role.
  A shared membership close publishes one post-commit `DocumentClosed` fact:
  affected primaries move to MRU, affected secondaries clear, and exact-client
  editor SSOT replaces or disposes the visible Monaco model.
- Browser, Electron, GeckoView, and Cefrium use this shared-frontend contract.
  A future Electron window must allocate an explicit distinct client identity.
- Frontends use their own lanes only: editor `/rpc/editor`, Explorer
  `/rpc/explorer`, host `/ui_ipc`, Sidebar `/sidebar_ipc`, terminal `/terminal`,
  WBA `/wba`, and framework console `/te2_console`. The standalone terminal
  additionally publishes IME focus/blur hints through `/ui_ipc`.
- Python Socket.IO namespaces share `/api/app/code_te2/socket.io` and may use
  one browser-realm Engine.IO manager. WBA remains a direct hot path at
  `/api/app/code_te2/services/wba/socket.io`; former full paths and manifest
  aliases are request-compatibility aliases only.
- Explorer, editor/Python, direct editor/WBA, and UI IPC require strict
  `msgpack-v1`. Their codecs are respectively browser `src/rpc/codec.ts`,
  Python `frontend_rpc_codec.py`, and WBA's bundled MessagePack ESM codec.
  These lanes have no JSON fallback. Sidebar IPC retains its established codec.
- `CODE_TE2_RPC_CODEC_METRICS=1` enables default-off codec metadata on stdout;
  its worker-shell declaration is `0` and it is inert when disabled.
- Direct WBA language intelligence remains frontend-to-WBA. MessagePack changes
  only its application payload codec; never route WBA hovers, completions,
  symbols, semantic tokens, inlay hints, or similar calls through Python.
- App-lane Socket.IO is websocket-only. Requests emit only while connected;
  notification lanes use `volatile.emit`. Disconnect rejects in-flight calls,
  drops notifications, clears `sendBuffer`, and requires reconnect handlers to
  rebuild authoritative state. WBA recovery remains disabled.
- Cross-surface action flow is frontend -> own backend -> target backend hook ->
  target notification. Do not couple frontend lanes directly.
- Code TE2 Git/search jobs use Rust pipe services. The old generic Python Git
  job registration/listener is gone; retained archive/file-explorer job records
  live under the framework data root without a global HTTP route.

## Code TE2 Persistence And Sidebar Ownership

- Code TE2 project sidecars, draft indexes, history, and agent icons live under
  `$TE2_DATA_HOME/code_te2`; preferences under `$TE2_CONFIG_HOME/code_te2`;
  Sidebar/code-server sockets under `$TE2_RUNTIME_HOME/code_te2`; browser
  console logs under `$TE2_CACHE_HOME/code_te2`. Project diagnostics live in
  `.code_te2/diagnostics`.
- Startup does not probe/import the former `cm6_editor`, `cm6_sessions`,
  `termux-extensions-2`, or `.code_cm6` roots. Bounded one-time moves map the
  old app-state/layout keys to `code_te2`; canonical destinations win.
- The generic worker resolves built-in backend module identity by package path,
  not public app id. Explicit `TE2_APP_ROUTER` is authoritative; legacy
  `<app_id>_bp` supports only unconverted out-of-tree apps.
- Sidebar ledger v2 stores shared membership, stable slot identity, lifecycle /
  readiness, and surface metadata. It does not own dock order or a global active
  presentation. See proposed `CODE_TE2.md` §45 for the full ownership split.
- Each host owns versioned local presentation state: stable host order,
  foreground, last-agent host, and embedded/hidden/detached mode. Browsers use a
  bounded origin/project Local Storage map; Electron uses validated preload/main
  IPC with an atomic XDG-config map. GeckoView/Cefrium use one application-private
  Android store keyed by stable client id, selected upstream framework origin,
  and normalized project path because random relay-port origins are not durable
  storage authority. Transient presentation ids are never durable. Exact former
  identities migrate once; canonical records win.
- WBA reset/disconnect/startup snapshots are non-authoritative and cannot prune
  Sidebar ledger membership or client preferences. Only a complete
  authoritative snapshot or explicit lifecycle removal prunes the active
  project partition; inactive project records remain parked. Recovery is
  event-driven with no polling or membership grace timer. Each host projects
  the global ledger through its current normalized project before presentation
  reconciliation; unscoped app and URL slots remain globally visible.
- Backend/startup Sidebar activation replay is coordination metadata and cannot
  reveal a locally hidden extension view. Only an explicit launcher/app-drawer
  action in that client may change `hidden` back to `embedded`.
- A host's empty Sidebar slot list is non-authoritative until its first ledger
  snapshot and cannot prune or overwrite loaded presentation preferences.
- Sidebar mentions are exact-client presentation actions. Producers include the
  caller client id, stable agent host id, and current transient presentation id.
  Python validates those against the live host, ledger membership, conversation,
  and registered app peer, derives the conversation from the ledger slot, and
  emits only to that app room. Re-created hosts must republish a fresh identity;
  missing/stale targets fail with no global-active/broadcast fallback.
- ALS-RS resolves outbound Sidebar IPC from injected `TE_FRAMEWORK_URL`, then
  `TE_PORT`, then standalone `8089`; its own `12459` listener is unrelated.
  Each reconnect re-registers the exact `als-rs` peer before targeted routing.

## Code TE2 Search

- Progressive file/content search uses Rust `service.search`; Python
  `explorer/services/search_sessions.py` owns session/cache adaptation, not
  searching. Full protocol, limits, and UI behavior: `CODE_TE2.md` §6.6.
- File/folder name search is an inline sibling projection inside the Explorer
  root card. It preserves the normal tree DOM/open state, expands hit ancestors,
  shallow-hydrates direct directory hits, and exits to one focused directory on
  a directory selection. A dedicated `🔭` header button opens the separate By
  contents, By changes, Drafts, and Diagnostics advanced overlay.
- Name-search shallow hydration is one bounded Rust `fs.listDirectories` pipe
  request assembled into the personal results payload by Python. The browser
  never issues one `explorer.list` RPC per matching directory. It constructs
  the complete projection off-DOM, attaches it once, applies aggregate Git and
  diagnostic decorations once, and changes only hit classes during next/previous
  navigation.
- Directory selection is backend-authoritative. `explorer.openDirs.set` persists
  the selected directory/ancestor chain, replies with its authoritative set and
  shallow listings, and publishes `ExplorerRenderStateChanged`; every project
  client reconciles its normal-tree DOM from `explorer.openDirs.updated` before
  the invoking client closes the inline search projection. After dismissal, the
  client allows 350 ms for layout to settle, then centers the exact directory if
  the project is unchanged and search has not reopened.
- Enabled Explorer sticky headers remain mounted throughout inline name search
  and keep its query controls pinned. First-hit auto-scroll is allowed only in
  that mode; with sticky headers disabled, typing never moves the tree, while
  explicit previous/next navigation still centers the selected hit.
- Sticky-header recomposition preserves the existing search input while it is
  bound to the same authoritative root input. Geometry and scope changes update
  controls and menu ownership in place; only a real source change or search-mode
  exit replaces the node. Never refocus a replacement as an IME workaround.
- Sticky push uses the represented source directory's rendered border-box bottom
  as its exact subtree boundary, with an 8 px visual lead matching the card's
  lower-left radius. Do not infer scope end from a later row or use a fixed
  ancestor-gap compensation; nested card spacing is already in that box. Very
  large, deeply expanded trees retain minor transient sticky animation artifacts
  while browser layout measurements settle.
- Explorer API: `explorer.search.run`, `.more`, `.moreInFile`, and `.cancel`.
  The stale `search:query` bus event is gone. Every content query injects
  `maxMatchesTotal: 700`; terminal results carry truncation metadata.
- Supersede, overlay close, and project switch must cancel and remove sessions.
  Search benchmarks enter through the normal scheduler so debounce,
  correlation, and cancellation semantics are exercised.

## Code TE2 Documents And WBA

- Read `CODE_TE2.md` §39 for logical documents, multi-client facades,
  metadata-first reconcile, WBA operation gating, foreground transactions,
  reconnect, activation, provider selection, and `workspace.findFiles`.
- Key invariants: one role-neutral extension-host document per canonical path;
  one synthetic editor facade per stable client; `editor.openComplete.publish`,
  not WBA acknowledgement, completes a visible Monaco open; Python materializes
  only background documents WBA identifies as missing/stale.
- Reconciliation protects the union of retained facade paths and in-flight
  opens. Releasing one facade never releases a shared document another client or
  open retains. Same-client/path/generation WBA opens are idempotent.
- Admission occurs before active/recent sidecar mutation. Reject known binary,
  media, archive, object, and font files; reject extensionless executables and
  disk/draft content over 375 KiB. Source formats, including `.sh`, remain open
  by default.
- Direct diagnostics are WBA-to-Monaco state. Python's diagnostics bridge feeds
  Explorer/Problems only; it never nudges editor diagnostics. See §33 for
  owner-keyed markers, reconnect snapshot replay, and bounded retention.
- Full-document semantic-token prewarming is a retained-document optimization;
  it uses real full providers only, pauses for visible opens, and never invents
  ranges. Exact cache identity/eviction and provider rules are in §23.

## Code Server, Extensions, And UI VSIX

- `webWorkersEnabled` selects mutually exclusive Worker and Code Server modes.
  Worker mode lazy-loads Monaco contributions/workers and never probes WBA or
  Code Server; Code Server uses WBA-backed metadata/providers. There is no
  mode fallback. See `CODE_TE2.md` §§11, 23, 24, 30, 34, and 41.
- The supported managed Code Server runtime is private and pinned. The executable
  path, mutable User/extension/settings state, runtime socket, installation
  rules, and no-global-code-server policy are specified in §41. Do not vendor
  the runtime or let WBA resolve the user's global code-server configuration.
- WBA receives exact generated configuration, extension-manifest, and User
  settings paths through Framework-Shell environment. Production RPC ids come
  from generated managed-runtime config; defaults are pinned fallback only.
- Languages & Extensions supports User and Workspace settings only. User
  settings materialize atomically to Code TE2 private code-server User data;
  workspace settings project from the active `.vscode/settings.json`.
- Extension activation is event-wide; provider dispatch matches every selector
  against exact language, scheme, authority, and path and aggregates matches.
  Pattern-only selectors remain valid. Do not add language-specific routes.
- UI VSIX is deliberately bounded. Existing registry and settings contracts stay
  authoritative; workspace-scoped activity webviews, panels, secure opaque
  sandboxing, document recovery, commands/menus, storage, and fixed webview
  theme are fully described in `CODE_TE2.md` §44.
- Legacy file-watcher extension API bridge is removed. Do not restore its broad
  watcher or `te2.onFilesChanged` command bridge.

- Open VSX marketplace installs are artifact-driven: resolve exact metadata,
  accept only identity-preserving Open VSX/CDN URLs, stream a bounded VSIX plus
  published SHA-256, verify before invoking the managed local-VSIX path, and
  confirm the expected id afterward. Do not restore Code Server
  `publisher.name@version` gallery installation; Android Node is classified as
  web and filters usable workspace/Linux extensions before install.

## Editor, Mobile, And Terminal

- Keep Monaco host `z-index: auto`. Its outer host overflow is visible and
  content/glyph hovers share the `300` widget tier with Find; an opened host
  menu/modal/body context menu or mobile Explorer/Sidebar isolates the complete
  editor at `z-index: 0`, so active host surfaces remain above every Monaco
  popup. Default font is vendored JetBrains Mono Nerd with ligatures. Code TE2
  has no menubar: File/Edit/Editor/View and Git branch selector are toolbar
  controls. See `CODE_TE2.md` §8 for the full stacking contract.
- File tabs derive from existing open/Git/draft/diagnostic facts. Decoration
  rendering must not reload sidecars off-thread. A red asterisk immediately
  before the filename marks a draft; discard is confirmation-gated.
- Run execution is backend-owned and serialized per project. Profile ownership,
  candidate selection, draft-save transaction, state projection, URL surfaces,
  preferred-port routing, and native development runtime are in `CODE_TE2.md`
  §37. There is no routine run-profile polling.
- The standalone terminal supports only the Node shellspec. Browser traffic is
  strict one-object-per-frame MessagePack; FWS pipe traffic is length-prefixed
  MessagePack. Node owns pty, headless xterm, 5,000-row scrollback, sequence,
  and reconnect checkpoints. There is no JSON/base64 shell fallback.
- Standalone Terminal lifecycle/control uses websocket-only `/terminal` at
  `/api/app/terminal/socket.io` with strict MessagePack payloads. One FWS
  snapshot plus lifecycle events owns generation-fenced revisioned shell-list
  projection; frontend selection remains client-local. The frontend has no
  application-control HTTP fallback or lifecycle polling.
- Standalone Terminal soft keys are two fixed seven-key rows: `ESC`, `≡`, `-`,
  `HOME`, `↑`, `END`, `PGUP`, then `TAB`, `CTRL`, `ALT`, `LEFT`, `DOWN`,
  `RIGHT`, `PGDN`. `≡` only opens the shell drawer and has a 300 ms capture
  guard against activating newly overlaid controls. Other action keys use
  synthetic keydown/keyup on xterm's active textarea so xterm owns escape
  translation. Ctrl is one-shot with double-tap lock; Alt is independently
  one-shot; combined modifiers are supported. Standalone Python transport
  ingress decodes to `object` and validates mappings rather than propagating
  inferred `Any`.
- Standalone Terminal directional soft keys emit immediately, repeat after
  420 ms every 55 ms, and retain the exact xterm/textarea plus Ctrl/Alt snapshot
  for the complete pointer hold. Release/cancel/lost capture, window blur,
  document hiding, or disposal stops repetition; one-shot modifiers are
  consumed once when the gesture ends.
- The standalone key dock and its header `Keys` toggle are Android/mobile-only;
  visibility defaults on and is client-local/non-persisted. Plain dash uses a
  guarded textarea `insertText` event because Android xterm suppresses
  printable keydown, while modified dash remains keyboard-event-owned.
- The standalone Terminal's initial list and minibar share one client-local
  `Show exited` checkbox. It defaults off, is not persisted or broadcast, and
  filters only rendered cards while preserving the authoritative shell snapshot.
- A standalone Terminal card is active only when it matches that frontend's
  client-local `activeId`; `aria-current` and the selected accent are separate
  from shared shell alive/exited status.
- Touch selection source/deployment, gesture menu, and build process are in
  `CODE_TE2.md` §35. The mobile key dock and Gecko-only keyboard recovery remain
  Code TE2 UI affordances; do not apply Gecko recovery to other renderers.
- The mobile key dock is visible by default with two rows. Ctrl is one-shot on
  one tap and locked on double tap; Select/Shift persists until disarmed. The
  horizontally scrollable translucent rail owns hover, context, cut/copy/paste,
  and Second Window actions while Save remains pinned right and reserves the
  existing Gecko keyboard-recovery slot.
- The four Code TE2 arrow keys use the same 420 ms/55 ms hold cadence and
  snapshot the primary Monaco, secondary Monaco, or terminal-drawer target plus
  modifiers at pointer-down. Pointer capture and lifecycle cancellation bound
  repetition; one-shot Ctrl/Alt apply through the complete hold and are consumed
  once on completion.
- The primary mobile host owns one shared special-key dock for both Monaco
  clients. Positive primary/secondary focus selects its target; Terminal focus
  remains a temporary override. Each editor realm owns a local translucent
  action rail and only the selected realm renders it. The retained secondary
  iframe receives typed key, panel, and Ctrl/Gboard modifier projection through
  its exact-source, exact-origin presentation channel; hide/collapse/close
  returns ownership to primary. No Android or backend transport participates.
- Mobile fullscreen drawer layout is grid-constrained, not viewport-height
  arithmetic: the primary editor row collapses, the drawer fills the remaining
  bounded row, and the status plus explicit key-dock rows remain visible. The
  key row naturally collapses when the user dismisses the dock.
- Mobile Second Window Collapse is presentation-only and retains its renderer;
  Close clears the secondary foreground, disposes Monaco, destroys the iframe,
  and removes the tab. Opening the bottom-drawer shell is independent of
  terminal activation; non-terminal and empty drawer opens never create a PTY.
- Android Gboard/Monaco IME rules are in §35. Keep the detached textarea,
  per-frame coalescing, `inputType`, line-break treatment, and Android-specific
  EditContext decision intact; never reinstate the old raw-key newline filter.
- Android custom xterm input uses the guarded cumulative textarea as the sole
  printable-text authority in both terminal surfaces. Its upstream keypress
  fallback is bypassed in that mode; keydown remains authoritative for
  non-text and modified terminal keys. Enter/Ctrl+C immediately reseed after
  clearing the helper; key code 229 and ordinary printable keydown also repair
  a missing guard before native insertion. A reset-stable source input hook
  lets the shared Ctrl helper consume Gboard `InputEvent.data` exactly once and
  restore that guarded projection without textarea inference. Monaco retains
  its established key-event adapter. Non-Android and screen-reader paths remain
  upstream.

- Fresh Code TE2 preferences default to draft mode (`autoSave: false`) with both committed and draft inline-diff overlays disabled; persisted user choices still override those seeds.
- Fresh Code TE2 editor preferences use the vendored `github-dark` theme. The
  obsolete `cm6-dark` seed migrates once to that theme; explicit selections,
  including `github-dark-default`, remain authoritative.
- Android IME context switching is opt-in (`false` when unset). Android Settings refreshes native notification/power state on foreground events only, and both renderer activities resynchronize `PersistentNetworkService` in `onResume` after a notification-permission grant; neither path polls.

- Code TE2's terminal drawer uses its existing websocket-only `/terminal`
  Socket.IO lane for correlated control and generation-fenced checkpoints; its
  frontend makes no terminal control/history HTTP requests. Reliable register
  and commands are separate from volatile input/resize. A bounded five-shell
  Pyte registry owns 5,000-line headless screen/scrollback state. It parses the
  complete raw log off-loop, uses FWS chunks only as event wakeups, and consumes
  exact flushed-log byte ranges. Browser xterm receives one ANSI checkpoint
  plus offset-fenced raw binary deltas; there is no raw-tail replay, textual
  overlap guess, polling, or decoded-text fallback.
- Code TE2 never resizes retained Pyte screens in place. PTY dimension changes
  mark the projection stale while live raw deltas continue; the next checkpoint
  reparses the canonical raw log once, off-loop and directly at the requesting
  client's dimensions. This prevents Pyte cursor preservation from creating
  synthetic blank rows without replaying history during routine viewport resize.
- Drawer shell lists join `ProjectSidecar` membership/titles/active identity
  with compact facts retained by the existing FWS snapshot/event bridge. Menu
  and register paths never scan every shell through the manager; identity is
  emitted before independent off-loop history and list projection.

- Mobile xterm touch selection combines a source-owned route in the maintained
  `xterm-te2` fork with one external, mobile-UA-gated adapter shared
  byte-identically by standalone Terminal and the Code TE2 drawer. Xterm owns
  the transparent capture surface, irreversible scroll classification, and
  disposable synchronous hook; the adapter owns public-API selection, handles,
  and Copy/Paste/Select all actions. Long press uses xterm's own word-boundary
  implementation, and drag extends a direct anchored cell range with no
  synthetic mouse lifecycle. The adapter claims touchstart synchronously so
  Chromium cannot open its native long-press context path and blur the IME, and
  xterm retains that claim through all later events in the touch sequence so
  stationary pending moves cannot leak into native scrolling. Completed taps
  alone replay a detail-1 xterm mouse sequence. Selection-handle drag resolves
  three terminal rows above the finger for target visibility. Its fixed body-level
  UI sits above xterm's own touch-capture layer and otherwise derives its
  `z-index` from xterm's outer host rather than using a global maximum, keeping
  it below Sidebar and shell-drawer overlays. The published editable source is
  branch `te2-mobile-touch-routing` at
  `1d71ed0732d592980eb0960ce3da001213d2636e`, based on xterm 5.3.0.

- Mobile secondary-editor ownership is claimed from capture-phase pointer/focus
  events on the persistent secondary editor frame, then projected through the
  existing presentation channel. Do not make the handoff depend only on
  listeners attached to a disposable Monaco widget DOM node.

## TE2 Console And CLI

- Framework console uses `/te2_console` on `/te2_console_ws/socket.io` and
  persists transcript JSONL under `$TE2_CACHE_HOME/console`. Its canonical
  events are register/log/eval/evalResult/evalCancel/replay/clear.
- `console_bridge.js` is bundled into `host.js`; it registers worker metadata,
  serializes console calls, races eval with the Python timeout plus two seconds,
  rejects pending evals on disconnect, and maps `undefined` to `null`.
- `te2 console list-workers`, `eval`, `tail`, and `search` are the supported
  CLI. List/eval require the live framework; tail/search read the transcript.
  Bounded newest-first reads power drawer replay/inventory; search streams.
- Console telemetry uses volatile Socket.IO and bridge teardown clears owned
  listeners, sockets, and pending evals. Detailed observability behavior is in
  `CODE_TE2.md` §25.

## Build, Publication, And Paths

- Package/CLI metadata is `pyproject.toml`; Python runtime requirements are in
  `requirements.txt`. Release versioning synchronizes package/Rust, Code TE2
  version asset, app manifests, versioned frontend URLs, launcher, and shipped
  Electron distribution. Dependency/protocol schema versions are separate.
- Code TE2 frontend handoff requires `npm run typecheck` and `node build.mjs` in
  `app/apps/code_te2`. There is one browser output, `static/dist/host.js`; do
  not restore standalone `editor.js` or Monaco bootstrap requests.
- Generated bundles, vendor trees, Android asset copies, and release candidates
  are publication output, not editable source unless an approved task explicitly
  targets them. Build wheels from clean isolated staging; never package the
  working directory, bytecode caches, profiler output, or build intermediates.
- Canonical `TE2_*_HOME` overrides are final roots. Otherwise resolve XDG bases
  plus `/te2`, with `$HOME` fallback for cache/data/config and a private
  `te2-$UID` runtime directory. Bootstrap exports resolved roots to Rust and
  workers; Android storage is separate.
- Framework builds are optimized by default; `--debug` is opt-in. Cache builds
  use one cross-process lock for build/validation/atomic publish/pruning; retain
  incremental Cargo artifacts but only the chosen validated final binary.

## Android Client

- GeckoView in `android/app` is the primary Android renderer. The removed system
  WebView is not a fallback. Isolated `:cefrium` evaluates Cefrium; use
  `CODE_TE2.md` §42 for its module, relay, inspector, IME, and validation rules.
- Android's pinned build/runtime tuple, 16 KiB APK alignment audits, and R8
  MessagePack keep rules are source-controlled release contracts. Verify current
  values from Android build files rather than duplicating versions here.
- `MainActivity` is sensor-portrait. Android Settings are local
  `SharedPreferences`, never framework Settings APIs. The runtime service owns
  strict-MessagePack websocket-only UI IPC; native console event payloads remain
  JSON.
- Do not conflate relays: Rust framework app/Socket.IO proxies expose public
  app/service mounts and forward to known loopback workers/services; `AndroidFrameworkRelay` gives native clients a local browser origin; serves
  native routes/assets, then forwards framework traffic upstream. Gecko/Cefrium
  bind it; Run Target is a separate client port relay. See §§36–38 and 42–43.
- `PersistentNetworkService` owns Android relay, Run Target route projection,
  UI IPC, and native console. Activities observe it; ordinary recreation or
  backgrounding does not close its transports. Cold restore waits for relay plus
  a fresh authoritative route snapshot; routes are never persisted as authority.
- Run Target routing, remote locality, generation fencing, and no-polling rules
  are shared with §37. Native inspector target ownership is separate from those
  routes and from framework Socket.IO; Gecko-specific details are §43.
- Stable Android identity is application-private. Primary and mobile-secondary
  editor identities rotate atomically on reset; `gv_native=1` plus explicit
  renderer identity preserves OTA compatibility. Random relay origins are not
  identity storage.
- Android Sidebar presentation state is also application-private, using one
  shared implementation but separate sandboxed records per APK. Gecko reaches
  it through the established
  WebExtension/native-message bridge and Cefrium through native query; records
  are bounded and partitioned by client id, selected framework origin, and
  project. No native presentation polling or backend authority is introduced.
- Android assets are authoritative from materialized `filesDir/editor_static`,
  seeded by APK/OTA. Gecko/Cefrium serve declared files locally, fail closed on
  missing files, reject root `/sw.js`, and use the established scoped cleanup.
- Debug/staging APKs use the repository development keystore; release variants
  do not. Retrieve the current fingerprint from Android source when an install
  mismatch requires investigation rather than storing it here.

- Android framework bookmark selection immediately persists and activates the
  selected endpoint through the existing native Settings transaction.
  `PersistentNetworkService.configure` remains the sole owner of relay
  retargeting, stale route teardown, and control-plane reconnection; the shell
  must not duplicate that logic.

- Cefrium's current native integration disables Chromium multi-touch and
  double-tap zoom through `GestureListenerManager` and resets ordinary CEF zoom
  to 100%, but live acceptance proved that this does not disable every Cefrium
  page-zoom path. Complete zoom suppression remains open. Code TE2 applies
  a renderer-scoped 16 px floor to the exact Monaco editor IME textarea and
  Find/Replace input so Chromium does not apply readability zoom to inherited
  10 px focused controls; the native page policy separately retains
  `preventScroll`.

## Desktop Client

- `desktop_client/electron/` is the active Linux desktop client. GTK/WebKitGTK
  is behavioral reference only; the Electrobun experiment is gone.
- Electron uses the trusted `te2-desktop://shell/` root, separate framework
  `WebContentsView`, one loopback relay for approved assets/HTTP/SSE/Socket.IO/
  WebSockets, and frozen exact-view allowlisted `window.te2Electron` commands.
  App URLs carry `gv_native=1`; native Quit returns to the launcher.
- Full Electron route projection, owner/shell relay lifetime, Sidebar native
  presentation, run-target policy, and desktop settings are `CODE_TE2.md` §38.
  It uses strict-MessagePack UI IPC snapshots and no route polling.
- Electron may create its native UI IPC client before Code TE2's worker exists.
  The app-prerequisite event must reconnect that existing client before a
  bounded wait for the authoritative route projection; an initial namespace
  refusal must never leave app launch waiting indefinitely.
- Electron persistent state atomically owns stable primary/secondary client ids,
  project-partitioned Sidebar presentation, and bounded secondary-editor
  records. The optional second editor is one explicit client: it shares
  membership/drafts/WBA logical documents but has its own authenticated UI IPC,
  editor, and WBA lanes.
- Electron launch intentionally uses `--no-sandbox`. Local-framework launching
  is an Electron-main controller; it owns only its exact child and the optional
  bootstrap stdio-control lifecycle plane, never a second framework data plane.
  A running owned child retains an immutable copy of the launch configuration it
  actually used. Launch-config edits may be saved while it runs, but apply only
  to the next start and cannot change the active process port/identity.
- Desktop framework bookmark selection is an immediate connection intent. It
  enters the same Electron-main `saveConnection` transaction as Save; the
  renderer never persists settings or retargets the relay itself.
- Desktop settings v2 adds opt-in `autostart` plus a canonical
  `preferredAppId`. After the launcher renderer announces readiness, Electron
  checks only the selected configured framework, resolves the live catalog, and
  invokes the ordinary app-open plus app-shell/readiness path. Missing framework,
  app, open, or readiness leaves the launcher interactive with a bounded status;
  startup never implicitly launches a missing local framework.
